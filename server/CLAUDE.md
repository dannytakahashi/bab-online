## Key Architecture Patterns

**Server:**
- `GameManager` singleton manages the main room, lobbies, all active games and tournaments (the matchmaking queue is gone: V1_REMOVALS #2)
- `GameState` encapsulates all state for a single game
- `rules.js` contains pure, stateless game logic functions (highly testable)
- Socket handlers wrapped with validation, rate limiting, error handling
- Timers never call into server code bare: an uncaughtException exits the process (exit 1, Railway restarts it, every game is dropped), so use `utils/safeTimer.js` `safeTimeout(fn, ms, label)` / `safeInterval` (logs and carries on) or a game's `game.setTimer`; `safeTimer.test.js` fails on a new bare timer (`docs/claude/server-infra.md`, Deploys)
- Socket.IO server options live in `server/socket/serverOptions.js` (cors + `connectTimeout` 10 s instead of the 45 s default: an engine that never joins the namespace is dropped, which bounds the iOS 1.1.0/1.2.0 stall after a long background below; `connectTimeout.test.js`)
- (The iOS stall after a long background: `iOSClient/CLAUDE.md`, iOS reconnect after a background.)

## Key Data Structures

**Card:**
```javascript
{ suit: 'spades'|'hearts'|'diamonds'|'clubs'|'joker', rank: '2'-'A'|'HI'|'LO' }
```

**Server GameState:**
- `seats`: {1..4 → seat record} (`server/game/SeatState.js`): who controls the seat and whether its owner is present (see Important Implementation Details)
- `players`: Map<seat socketId → {username, position, pic}> and `positions`: {pos → seat socketId} — a derived index of `seats` (display identity: the owner for a human seat, else the bot), written only by the seat transitions
- `entrants`: Map<socketId → {username, isBot, presence connected|disconnected|left}> before seating (set by `createGame`, null once 4 seats exist)
- `hands`: {socketId → card[]}, `bids`: {position → bid_value} during bidding, then {team1, team2}
- `stage` (internal, authoritative): `CREATED → DRAWING → DRAW_RESOLVING → TEAMS_ANNOUNCED → (DEALING → BIDDING [→ REDEAL → DEALING → BIDDING] → PLAYING ⇄ TRICK_RESOLVING → HAND_RESOLVING) ×13 → ENDED`, any live stage `→ ABORTED` (`server/game/GamePhase.js`). `epoch` bumps once on ENDED/ABORTED
- `phase` / `bidding`: read-only wire projections of `stage` — `phase` is 'waiting'|'drawing'|'bidding' (never 'playing'; it stays 'bidding' through play), `bidding` is false only from the end of bidding to the next deal
- `trump`: card, `isTrumpBroken`: boolean
- `bidClock`: {pos, turn, startAt, endAt, durationMs, running, toppedUp} of the bid turn the bid clock was last armed for, or null; `bidTimeouts`: {pos: timeouts in a row} (the strike rule). Both DERIVED (never saved; Bid clock below)
- `playedCards`: [pos1Card, pos2Card, pos3Card, pos4Card]
- `tricks`: {team1: count, team2: count}
- `hsiValues`: {pos → HSI} of the current deal (`rules.calculateHSI` = `server/game/hsi.js` since 2026-11-22: 55 + 300 × the expected share of the hand's tricks, from card values fitted on Mary self-play; 130 = an average hand at any size, the 70 / 195 colour bands and lifetime Avg HSI keep their meaning; it replaced the original points count, 0.640 → 0.714 rank correlation with tricks won; the file's header has the formula, the evidence and when to refit), server-side: each seat owner receives ONLY its own position's value (gameStart `hsiValues` with that one key, snapshot v2 `hsi` with nulls at the other three; spectators none), since 2026-11-21 (all four used to go to every owner, a hand-strength leak to a modified client); `server/testUtils/hsiGuard.js` (setupFilesAfterEnv) fails any Jest test in which a socket receives another seat's HSI (contract/README.md, Snapshot v2 `hsi`); `playerStats[pos].totalHSI` gets it once the bids keep the hand (`handlePostBid`, BIDDING → PLAYING), never for an all-zero redeal (2026-11-15: each redeal used to add a sample with no hand counted), so gameEnd `avgHSI` and the stored `totalHSI` / `totalHands` average one sample per counted hand. Stats already stored keep the old inflation (no backfill)
- `gameLog`: the last 500 lines (`addLogEntry(message, position, type, {from})`), `logTotal` counts every line ever added. A chat line (`chatHandlers.chatMessage`: the username its `chatMessage` broadcast names, a spectator's included; `BotController.sendBotChat`: the bot's name) carries its sender as an internal `from`, never on the wire: snapshot v2's log maps each entry to `{message, type, position, at}`. `buildSnapshotV2 {hideChatFrom}` leaves out the chat lines whose `from` the viewer blocked, and `snapshotHandlers.carrierFor` / `requestSnapshot` pass the receiving socket's `socket.data.blockedUsers` (rejoinSuccess, restorePlayerState, the spectator full state, stateSnapshot), so a resync never brings back chat both clients hid live (since 2026-11-16; before, every snapshot replayed it). System, bid and other lines are kept even when they name a blocked player. `from` is the NAME the line was shown under, not always an account: a bot quip's `from` is the bot persona ('🤖 …', `safetyHandlers` `isBotName`: never in `users`, yet blockable), and a spectator with no recorded name chats as the literal 'Spectator' (`chatHandlers.chatMessage` fallback). Anything that checks senders against `users` (deleting an account's chat, scrubbing deleted senders on adoption) must skip bot personas, or every bot quip reads as a deleted sender's. An admin rename or merge from the panel re-points `from` in every live game (`GameManager.renameChatSender(old, new)` → `GameState.renameChatSender`; `adminHandlers.renameAccountNow` both paths, `applyMergeNow` for every source, also on its "already complete" retry), since the blockers' lists now name the new account: a renamed spectator's earlier chat stays hidden from their blockers (findLiveActivity does not refuse a spectator). The visible text keeps the old name. Not reached: `scripts/merge-accounts.js` (another process; the line shows again to a blocker after their next sign-in, until the game ends). Tests: `server/socket/__tests__/snapshotBlockedChat.test.js`, `adminPanel.test.js` (rename and merge "chat … live game")

**Bid Values:** '0'-'13' for numbers (a number may not exceed the hand size, so '13' only on the 13-card hand: owner 2026-11-11, "technically legal, just very unlikely"; a plain 1x bid of 13 tricks), 'B'/'2B'/'3B'/'4B' for bores (2x/4x/8x/16x multipliers; each level needs the one below on the table and may be bid once per deal: `isValidBid` refuses a skipped or repeated level, owner 2026-11-11). `rules.BID_VALUES` is the one list (the Joi `playerBid` schema and `GameState.validateBid` use it / `isValidBid`); Joi takes '13'/13 on any hand and `isValidBid` refuses it below 13 cards (`actionRejected invalid_bid`). For the lead every bore outranks a numeric 13 (`findHighestBidder`); bots never bid 13 (`server/socket/__tests__/bid13.test.js`)

## Game phase FSM

- Game phase FSM (`server/game/GamePhase.js`, `GameState`): the stage changes only through `game.transition(from, to)` (every call site reads `if (!game.transition(F, T)) return;` — an illegal call throws under Jest / `BAB_FSM_STRICT=1`, logs and fails closed in production), `tryTransition` (the DRAWING → DRAW_RESOLVING latch, so the draw resolves exactly once) and `terminate(io, ENDED|ABORTED, event, payload)` (final event out first, then epoch bump + cancel all game timers). Never write `game.phase`/`game.bidding` (getters; a write is a reported violation) and never gate on flags — gate on `game.stage` (`acceptsTurnInput()`, `actionTypeForTurn()`, `isPreSeating()`). Lifecycle waits use `if (!(await game.pause(ms))) return;` (presentation holds: `game.hold(kind, ms)`, see Pacing) and timers use `game.setTimer(key, ms, fn)` (`grace:<pos>` per-seat reconnect grace, `abandon`, `draw:watchdog`, `resume` (trick/hand hold); `afk:<pos>` the turn watchdog, see AFK below; `bidClock` the bid clock's pre-wait and clock, see Bid clock below; `stall` the progress watchdog, see Bots; bot bid/play/draw/chat stay in `BotController.pendingActions`), so nothing runs or emits after end/abort; BotController timers check `game.epoch`, and `broadcast`/`sendToPlayer` drop everything from a terminal game. `recordDraw` is the only writer of draw state. Abort only through `socket/gameLifecycle.abortGame(io, game, reason)` (abortGame to the room incl. spectators → ABORTED → `GameManager._retire`: bots, room, every `playerGames` entry for the game → lobbiesUpdated → DB/tournament follow-up); the draw starts only through `gameLifecycle.beginDraw` (also auto-draws for sockets that left/disconnected during the pre-draw countdown). The end path sends `gameEnd` before persisting stats. ## Pacing

- Pacing (`server/game/pacing.js`, the only home of presentation delays; Cut for a buck's `CUT_GATHER_MS` 15000, `CUT_REVEAL_MS` 4000, `CUT_WINNER_MS` 6000 on every profile but zero, whose values are 0; read `pacing(game).X` at call time, never destructure): profiles `standard` (default), `legacy` (pre-retune values, rollback knob), `fast` (dev only, ignored in production), `zero` (tests only) via `BAB_PACING`; bot ranges are `[min, span]` with ONE `Math.random()` per action (`BotPlayer.getActionDelay(type, {kind})`; `BotController.actionKind` picks firstBid/bid, afterBidding/afterTrick/forced/follow at schedule time from public state only — forced = the hand's last card, never "one legal card", which would leak a void; leads never use the forced range). `SHIPPED_IOS_FLOORS` is what the App Store build needs (measured on 1.1.0 build 2, iOS source f05d264; 1.2.0 builds 4 and 5 have identical animation timings, checked 2026-11-12 and, for build 5's Draw for Deal refresh, 2026-11-13) — it decodes but never reads resumeInMs and animates on receipt, so the server's gaps are still what it gets; unlike 1.0.0 it rolls a refused action back (actionRejected) and collects a trick in its own layer (no guarded clearTrick), so its floors are lower: BOT_FIRST_BID 500, BOT_LEAD_AFTER_BIDDING 300, BOT_LEAD_AFTER_TRICK 400, HAND_END_MS 400 (the rest unchanged; evidence in pacing.js). `pacing.test.js` holds every non-zero profile to it, and standard + legacy also to `IOS_1_0_FLOORS` (the old build's floors) because `UPGRADE_GATE=off` lets 1.0.0 play again; `pacingBudget.test.js` checks every gap against the larger of the two. ## Get Your Bid

- Get Your Bid (owner 2026-11-24; rules for players: `docs/RULES.md` "Get Your Bid"): a second game mode, a lobby option, web only, never a tournament table. Three seats, no teams; the base game's card play (every other seat is an opponent of a HI joker lead); each seat scores only for taking exactly its bid (10 + the bid, an exact 0 scores 5, anything else 0, never negative); no bores; on hands of 5 or more cards the last bidder (the dealer) may not make the bids add up to the hand (the Forbidden Bid; taking exactly that many tricks anyway scores 1); all zeros is played, never redealt, led by the first bidder; no rainbow bonus (owner's scoring lists none: ask before adding one), no HSI, no /help, no tutorial, no stats.
- One engine, one flag: `server/game/gameMode.js` (`MODE`, `isGyb`, `seatsOf`, `GYB_CAP`). `lobby.mode` ('gyb', else absent) is set by `createLobby {mode}` (`GameManager.createNamedLobby`), carried by play again (`playAgain.originOf` / `openLobby`), and becomes `game.mode` (`GameManager.createGame(ids, {mode})`, `new GameState(id, {mode})`); fixed for the game's life. `game.seatCount` (3 | 4) and `game.isSolo` replace every hardcoded 4 on the turn path: `rules.rotatePosition(pos, n)`, `determineWinner(trick, lead, trump, n)`, `findHighestBidder(start, bids, n)`, `isLegalPlay({..., solo})`, GameState's draw / bid / play / `_stageErrors` checks, `SeatState.validateSeats`, `tableView.openTrick(game, n)` (n is passed, never read there: `assist/seatView` may only read its own field list), the draw paths' `drawIndex === game.seatCount`. Seat 4 simply never exists (`seats[4]` null; loops over 1..4 that null-check are unchanged). A new place that counts seats must use `game.seatCount`, never 4.
- The mode's own rules are pure functions in `rules.js`: `gybHandScore`, `gybForbiddenBid`, `isValidGybBid`, `gybSafeBid` (the bot fallback and the bid clock's timeout bid: '0', or '1' when 0 is forbidden), `gybDrawPosition` (the highest card sits at 1, no partner swap). `GameState.isBidLegal` picks the bid rule; `GameState.gybForbidden()` derives `{position, bid}` from the bids and the dealer (never stored).

The team fields keep their classic SHAPE and carry no meaning there (`score` stays 0/0, `bids` becomes `{team1: sum, team2: 0}` after bidding so the stage invariants hold, `tricks.team1/team2` still count by parity so their sum is the tricks played, mults 1, rainbows 0); each seat's tricks are `game.handTricks`. `gameHandlers.handlePostBid` has the mode's branch (no REDEAL, the lead from `findHighestBidder`, which gives the first bidder on all zeros); `handleHandComplete` splits into `scoreGybHand` / `scoreClassicHand` and the shared `finishGame`; `handleDrawComplete` skips `teamsAnnounced` and its hold.

- Tournament partners (owner 2026-11-24: "ideally you don't play with the same partner again during the tournament; if you must, it shouldn't be in a row"; `game/tournamentPartners.js`): `startTournamentRound` plans each round with `planRoundTables(usernames, t.partnerHistory())` instead of a shuffle into `distributePlayersIntoGames`, whose table shapes it keeps (balance unchanged). Only human partners count (a bot partner is never a repeat). A 4-human table is two human pairs, a 3-human table one pair and one member with a bot partner, a 2-human table two members each with a bot (they face each other, never partners), a 1-human table one member with bots; so a round is a choice of who gets a bot partner plus a matching of the rest, at the least cost: first no member partnered with the partner of the last round they played (a sit-out keeps the partner of the round before; a bot partner leaves none), counted per member (`inARow`: a pair who are each other's last partner, in a row for both, costs two; a reunion after one of them sat out while the other played with someone else costs one, so when every option repeats a last partner the planner never picks the pair of the round just before), then the fewest earlier partnerships (each earlier one counts), ties at random. Exact by branch and bound (stops at the first cost-0 plan; `NODE_BUDGET` 200,000 nodes, then the best found: only large rounds, where cost 0 always exists, since 8 or more members with at most 3 earlier partners each always have a repeat-free matching).
