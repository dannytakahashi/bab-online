# Ambient bot activity

Loads automatically when Claude reads a file under `server/demo/`; pacing (`AMBIENT_PREGAME`, `AMBIENT_IDLE_MS`) is in `server/CLAUDE.md`, Pacing.

- Ambient bot activity (`server/demo/ambientBots.js`): keeps one spectatable bot-vs-bot game running while someone could see it and seeds main-room chat with bot-persona messages (seeded at startup, rotating line after 30 quiet minutes), so the app is never an empty room (added for App Review Guideline 2.1(a) — reviewers must see other users' chats and games). On by default in production; `AMBIENT_BOTS=true|false` overrides (false: never started, no hook). On demand (owner, 2026-11-11): nothing runs at boot; every `GameManager.joinMainRoom` (all three join points: joinMainRoom, leaveLobby, a tournament's sendToMainRoom) calls the `onMainRoomJoin` hook, which starts a game on a 0 ms timer when none is running or pending (listed ~60 ms later, measured with the fake clock in `ambientBots.test.js`); demand = a socket in `gameManager.mainRoomSocketIds` (signed-in players only; gated 1.0.0 sockets never join) or a spectator of the ambient game, refreshed every poll; after `AMBIENT_IDLE_MS` (pacing.js, 10 min, also under zero) without demand the running game plays to its end and no new one starts — idleness never aborts a game. A wedged game (older than 90 min) is recycled through `gameLifecycle.abortGame` (spectators get `abortGame { reason: 'Game recycled' }` and leave the room). While in demand a finished game is replaced within `AMBIENT_CHECK_MS + AMBIENT_RESTART_MS` (5 + 5 s); `stopAmbientActivity` clears the poll, the wake timer and the hook; before the deal and while unwatched a demo game uses `pacing.AMBIENT_PREGAME` (draw/reveal/seating/teams ~0: those stages are unlisted), so it is listed ~0.1 s after its start and then plays at the standard pacing App Store review sees. Who sees the main-room chatter (owner, 2026-11-12: "only show the bot chats when the test1 user logs in"; `server/utils/ambientChatUsers.js`, read per call): env `AMBIENT_CHAT_USERS`, a comma list of usernames ignoring case, unset or blank = `test1` (the App Review demo account; if the review account changes, set the env to its name, never a password), `*` = everyone (the behavior before), `none` = nobody. The bot lines live in their own ring `gameManager.ambientMainRoomMessages` (cap 50, `addAmbientMainRoomMessage`), so they never push a human line out of `mainRoomMessages` (everyone else keeps the full 50 human lines); `ambientBots.postAmbientChat` sends each one live as `mainRoomMessage` to every `mainRoomSocketIds` socket of a listed account (`io.to(socketId)`; `*` keeps the one `io.to('mainRoom')` broadcast; schema `to: mainRoom | socket`), and `GameManager.mainRoomMessagesFor(username)` (all three join points' `mainRoomJoined.messages`) merges them by time into a listed account's replay (newest 50 of both). `CHAT_IDLE_MS` counts the newest line of either ring. Not filtered: the ambient game stays listed and spectatable for everyone, and its bots' in-game chat goes to the game room as before; human main-room chat is unchanged; report / block work on a bot line as on any (they never look the line up); the upgrade gate's update-only main room never reads either ring. Tests: `server/demo/__tests__/ambientChatVisibility.test.js`
