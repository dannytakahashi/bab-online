# Account admin: merges, admin panel, reset links, deletion

Loads automatically when Claude reads a file under `server/admin/`; the socket side is `server/socket/adminHandlers.js` and `authHandlers.js` (sessions: `docs/claude/server-accounts.md`).

## Merged accounts

- Merged accounts: `scripts/merge-accounts.js` turns duplicate accounts into tombstones `{ username, mergedInto, mergedAt }` (no password/tokens/stats). Sign-in/sign-up/restore on a tombstone tell the player which account to use (an admin rename leaves the same kind of tombstone with `renamedAt`, and merged tombstones a rename re-points get `targetRenamedAt`: for those the new name is told ONLY at sign-in with the target account's password, `authHandlers.hidesNewName`); leaderboard and player search exclude them; the admin panel can delete a tombstone to free its name; `getPlayerProfile` follows `mergedInto` (not `renamedAt` / `targetRenamedAt`); deleting the kept account deletes its tombstones. The kept account's `mergedFrom[]` is the audit log and the idempotency guard. Bot-game stats (`users.botStats`, docs/claude/server-infra.md Stats scopes) merge exactly like `stats`: `planMerge` carries `botStatsBefore/After` and `sourceAccounts[].botStats` (a source with only botStats is `add-stats`), `applyMerge` adds BOTH buckets in the SAME guarded `updateOne` that pushes `{username, stats, botStats, mergedAt}` to `mergedFrom` (never a second write), `TOMBSTONE_UNSET` drops `botStats`, `formatPlan` prints a `bot games:` line per account and the `botStats.<k>` changes, `mergeView` adds `accounts[].botStats` and `botStatChanges` and its `canonical()` hashes `botStatsBefore/After` (a bot-only change makes the preview stale); `findDuplicates` rows carry `botGamesPlayed` (sorted by all games). `gameRecords.team1Bots/team2Bots` (bot personas of bot games) are never re-pointed, renamed or anonymized: merge / rename / delete touch only `teamNPlayers`. Any new per-user data keyed by username must be added to `server/admin/accountMerge.js` (in-memory server state keyed by username — the profile caches, the sign-in throttle — cannot see a CLI merge; the caches' 60 s TTL and the throttle's 15 min window bound it)

## Admin panel

- Admin panel (owner, 2026-11-11: "allow me/my user and anyone designated admin to be able to do things like the merge duplicate accounts or send a password reset email etc. from ui"): `users.isAdmin: true` (+ `adminSince`, `adminSetBy`; `server/admin/adminRole.js`). The FIRST admin is set by the owner with `scripts/set-admin.js` (Account Admin below); then admins add/remove admins from the panel; removing a flag never leaves zero admins (remove, count, restore: two admins removing each other cannot both win; the CLI may, with a warning). Tombstones are never admins (refused; planMerge refuses an admin source; the tombstone write unsets the fields). Wire: ONE c2s `adminRequest {requestId, action, args}` and ONE s2c `adminResponse {requestId, action, ok, ...}` (`server/socket/adminHandlers.js`; actions in `server/admin/actions.js`: searchPlayers, createResetLink, signOutEverywhere, findDuplicates, planMerge, applyMerge, listReports, resolveReport, listAdmins, setAdmin, listAudit, listPlayers, deleteAccount, renameAccount; web only, excluded from Swift). Socket, not HTTP: the panel's socket is already authenticated, goes through asyncHandler (Joi envelope, `rateLimiter.adminRequest` 60/min) and reaches live sockets; no cookies, so no CSRF surface. AUTHORIZATION on EVERY request from the DATABASE (`authorizeAdmin`, one line per check, each with a failing test when removed): the socket is registered (signed in), the account exists, is not a tombstone, `isAdmin === true`, `users.socketId` is this socket (a stale/rejoin-only socket is refused) and `socket.data.sessionHash` is still a live session (`sessionTokens.hasLiveSession`: a set-password / sign-out-everywhere revokes admin at once). Anyone else gets ONE byte-identical refusal `{ok:false, error:'forbidden', message:'Not available.'}` for every action and target, before args are read (per-action Joi after that: `invalid`). `isAdmin: true` on signInResponse / restoreSessionResponse (additive, only when true) is DISPLAY only (the web menu's Admin entry; iOS 1.1.0 parses dictionaries and ignores it, f05d264 AuthSocketHandler). Audit: every request writes exactly one `adminAudit` entry `{at, actor, action, target, result ok|failed|forbidden, detail}` (forbidden ones by name; a signed-out socket only logs; `listAudit` and `listPlayers` (read-only views opened constantly) are not audited, though a refused request for them is; detail is names and counts, `redactDetail` drops token-shaped text); the reset page's use is audited as `useResetLink`. Merge from the panel: `mergeView.planView` (formatPlan's content as data, no picture bytes) + `planHash` (sha256 of the whole canonical plan); apply re-plans and refuses when the hash differs (`stale_plan`), requires the kept name typed exactly, and runs one at a time (in-process queue `serializeMerges`: a second merge of the same source re-plans after the first and is refused); it refuses a source playing right now from MEMORY (`GameManager.findLiveActivity`: a game in its draw has no activeGameId yet), then in one synchronous step locks the source names (`GameManager.mergeLocks`: signIn/restoreSession/token rejoin refused, lobbies/tournaments/startGameFromLobby refused) and signs out their sockets BEFORE the first write, unlocking when done; the retire write refuses a source with activeGameId/activeTournamentId or merged elsewhere (`applyMerge` result.notRetired, e.g. the CLI in another process), reported as a partial merge (`server`). Then it invalidates the in-process caches. Sign out everywhere: unset sessionTokens/sessionToken, then `authHandlers.signOutUser` (forceLogout + handleDisconnect + disconnect, the flow `disconnectPreviousSocket` shares). signOutUser reaches EVERY connected socket of the name: currentUsers, the socketId the revoke read (findOneAndUpdate `before`, also in `writePasswordHash` for reset links), and every socket whose `socket.data.username` claims it (set by signIn/signUp/restoreSession/token rejoin BEFORE the session write, given back on refusal: a second tab restored from the same saved session, and a sign-in whose write is in flight). After registerUser, signIn/restoreSession re-read the user (`sessionGoneSince`) and undo the sign-in if the session was revoked meanwhile, the name is merge-locked or the socket closed (a revoke after the write but before the registration). Players (`server/admin/players.js`; owner 2026-11-11: "a table would be helpful (like the leaderboard)"): `listPlayers` = every account newest first (_id), capped at `LIST_MAX` 500 with the true `total` (the panel shows a cap note); `searchPlayers` stays for the API. Row: created (_id time), last seen (newest session use), online, games (human games, `stats.gamesPlayed`), bot games (`botGamesPlayed`, `botStats.gamesPlayed`; its own sortable column, '—' for a tombstone; the merge preview has a Bot games column and a "Bot-game stats that change" list), admin, `mergedInto`, `renamed` (a rename's redirect); never password/session/IP data. Delete (owner: "ability to delete accounts from the admin panel"; `deleteAccount {username, confirm}`, the name typed exactly): `server/admin/accountDelete.js` is THE deletion, shared with the player's own `authHandlers.deleteAccount` (eraseAccount: open reset links revoked, gameRecords → '[deleted]', for an ADMIN delete the name `$pull`ed from other players' blockedUsers (their live sockets get the voice list only, `refreshBlockLists {emit:false}`: no `blockListUpdated`, since iOS 1.1.0 shows every one as a "Block list updated." alert; a player's OWN delete keeps other players' blocks, `pullBlocks:false`, so deleting and signing up again as the same name cannot clear them), reports KEPT and marked `reporterDeletedAt`/`reportedDeletedAt` (rows say reporterDeleted/reportedDeleted), then the user document (deleted by `_id` AND name: renamed meanwhile, nothing is deleted and it throws), then its tombstones (`mergedInto: name`); forgetAccount: caches, avatarStore, deletedUsernames; data first, user doc last, so deleting again finishes a stopped one; self-delete also signs out every other tab). The panel refuses an admin, the acting admin (self-delete has the password check) and a player in a game / tournament / draw (`findLiveActivity`, then the guarded write); runs in `serializeMerges`; locks the name + signs out in one synchronous step, then ONE guarded `findOneAndUpdate` (still not admin, not playing, not merged) revokes every session before anything is erased; partial failures are reported (`server`). A TOMBSTONE (merged or renamed name) is only deleted (`deleteTombstone`): frees the name, the kept account's games and stats untouched; its `mergedFrom` entry for that name moves to `mergedFromFreed` (history kept), since mergedFrom is the merge's already-merged guard and a new account with the freed name merged into it later must have its stats added; refused for the redirect of an unfinished rename (owner, 2026-11-11, agreed: keep tombstones by default for the sign-in redirect and to reserve the name; the admin deletes one to free it). Rename (owner: "ability to rename accounts from the admin panel"; `renameAccount {username, newName, confirm}`, the new name typed again; `server/admin/accountRename.js`): sign-up rules (`checkNewUsername`, profanity), taken ignoring case incl. tombstones (`findNameClash`; only the account itself may match: a case-only rename); refused for a tombstone and a player in a game / tournament / draw; `serializeMerges`; locks BOTH names (signUp refuses a locked name ignoring case: `GameManager.isNameLockedIgnoringCase`) and signs out first; open reset links revoked; ONE guarded `findOneAndUpdate` renames users.username AND revokes every session (REVOKE_ALL_SESSIONS: the saved web/iOS sign-in carries the username; the player signs in once with the new name and the same password), duplicate key = taken, then a case-variant re-check (also covers the non-unique fallback index) puts the old name back; then a redirect tombstone at the old name `{username: old, mergedInto: new, mergedAt, renamedAt, renamedBy}` (sign-up says taken, leaderboard / search skip it; the new name is PRIVATE (REN-REDIRECT-DISCLOSE: a player renamed on request may be getting away from someone who knows the old name): sign-in with the old name AND the account's password says "This account is now called X. Sign in as X." (`authHandlers.tombstoneMessage`); a wrong password is the normal "Invalid username or password!" and counts as a failed attempt; sign-up says only "That name is taken." (a case variant names the old name, never the new: `takenMessage`); restore gives the routine "Invalid session token"; `getPlayerProfile` does not follow it: "Player not found"); then gameRecords teams, reports (reporter, reported, resolvedBy), other users' blockedUsers (de-duplicated, live sockets refreshed), tombstones pointing at the old name (re-pointed and marked `targetRenamedAt`, so a merged name does not give the new name away either), adminSetBy. Accepted residual: games the players shared now show the new name (renamed everywhere, as asked). NOT renamed: adminAudit (history by the names of the time; the rename's entry links old -> new) and passwordResets history (username/createdBy of used/revoked links). A failure after the rename is `server` "... Rename X to Y again to finish" and the same rename again `resumed` finishes the shared documents: the guarded write sets `renamePending {from, at}` (cleared when everything moved), so the resume works even when the redirect insert itself failed (it writes the redirect then; a new account that took the old name meanwhile is refused, nothing moved); listPlayers rows carry `renameUnfinished` (the old name) and the panel offers Finish rename; an account with an unfinished rename cannot be renamed again or deleted until it is finished. Renames skip report sides marked deleted (an earlier holder of the name), and so do merge plans. An admin cannot rename their own account (it would sign the panel out before the answer). The blockers' live sockets get `blockListUpdated {success, blockedUsers, silent: true}` (web: no toast; iOS 1.1.0 ignores silent and shows its "Block list updated." alert: accepted for owner-run renames). Merges, deletes, renames AND a player's own Delete account share ONE queue (`server/admin/mergeQueue.js` `serializeMerges`; self-delete re-reads the account by _id and name and checks the merge lock on its turn), and a queued panel request is authorized again when its turn comes (`queued`: forbidden if the admin lost the flag or was signed out meanwhile). signUp re-checks for a case variant AFTER its insert (and undoes it), as the rename re-checks after its write, so a rename to "Bob" racing a sign-up of "bob" can never leave both. The rename dialog says the old name stays reserved and who is told the new name. iOS 1.1.0 (f05d264) after a rename: forceLogout / failed restore clear its token and show sign-in; signing in with the old name and the password shows the redirect under the fields. A deletion during an unfinished rename (the player's own Delete account; the panel refuses one) erases the OLD name too (SELFDEL-PENDING: `eraseAccount` reads `renamePending.from` and runs every step for it while the old name is free or still this account's redirect; a different account holding it keeps its data), so nothing of the person stays under a freed name. Reports: no `status` = open; resolve/dismiss with `resolvedBy/resolvedAt/resolutionNote`. Web: `client/src/ui/screens/AdminPanel.js` (wide kit Modal, WAI-ARIA tabs Players / Merge / Reports / Admins / Audit, confirm dialogs for sign out everywhere / remove admin / make admin, the merge's typed confirmation, one status line; a `forbidden` answer closes it and hides the entry; the Players table, its sort/filter, the row's More menu (WAI-ARIA menu button; Escape is taken on the window in the capture phase so it closes the menu, not the panel; destructive items last in the danger text color, never a filled red button) and the typed delete / rename dialogs (a refusal stays in the dialog) are `client/src/ui/screens/adminPlayers.js`), `client/src/admin/adminApi.js` (requestId-matched requests, the display flag). Tests: `server/socket/__tests__/adminPanel.test.js` (authorization matrix every action x 9 states, audit, token never logged, every tab signed out, merge races MRG-WIN; delete: tabs, records, block lists, links, reports, tombstones, refusals, the lock, partial; rename: a full scan for the old name, rules/taken/tombstone clash, in-game, locks, the clash re-check, partial + resume, rename vs merge serialized, leaderboard), realMongo (j) (k) (l) (list, delete, rename on the real driver), authSessions.test (revoke after the write: RST-SOCK), passwordResetRoute.test (two tabs, in-flight restore), realMongo (i) (concurrent merges, retire filter), `server/admin/__tests__/adminCore.test.js`, contract.test (e2), `client/src/ui/screens/AdminPanel.test.js`

## Password reset links

- Password reset links (`server/admin/passwordReset.js`, `server/routes/passwordReset.js`, `client/reset.html` + `client/src/reset/`): no email (none stored): an admin makes a link `https://<host>/reset#<token>` in the panel (shown once, Copy) and texts it. Token: 32 bytes `crypto.randomBytes`, base64url (43 chars), stored only as its SHA-256 in `passwordResets {tokenHash, username, userId, state open|used|revoked, createdAt, expiresAt, createdBy, usedAt?, revokedAt?}`; valid 24 h (`RESET_TTL_MS`), once: ONE `findOneAndUpdate({tokenHash, state:'open', expiresAt > now})` claim (two tabs: exactly one success; realMongo (g)); a new link revokes the player's older open ones (partial unique index: one open link per player); a merge revokes the retired names' links; `scripts/set-password.js` and Sign out everywhere cancel open links too (`setPassword.revokeOpenResetLinks`: locking an account down kills a leaked link). Every bad / expired / used / revoked / merged / deleted link is the SAME 400 `invalid_link`. The token rides in the URL FRAGMENT (never sent with the GET, so never in a request line, request log, proxy log or Referer); the page drops it from the address bar (`history.replaceState`) and POSTs it in a JSON body to `/api/password-reset` (JSON only, same origin only via Origin / Sec-Fetch-Site, no cookies; per-client bucket 10 / 15 min (an IPv6 client by its /64: `clientKey`) on every POST, while the global bucket (60, 1/s) and the 4-hashes-in-flight cap are charged ONLY by `gatedHash`, i.e. once the token named an open unexpired link, so junk from any number of addresses cannot lock real players out (SEC2-RESET-GLOBAL-DOS); Referrer-Policy no-referrer, Cache-Control no-store; `requestLogger` logs only the path for /reset and the API). The sign-up password rule (1-100); success = `setPassword.writePasswordHash` (the CLI's session revocation: every saved device signed out, stamp `passwordResetByLinkAt`) + `signOutUser` for live sockets; the page says "Password changed. Sign in with your new password on the app or the website." (iOS 1.1.0 then shows its sign-in screen: a failed restore clears its token and goes to `.signIn`, f05d264). The page is its own Vite input (`reset-[hash].js`, ~4 KB; `vite.config.js` fails the build if it imports the app, vendor or boot chunk; `reset.css` @imports tokens + kit so no chunk is shared; kit elements through `elements.js?page=reset`), so the phone gate never runs on it and no game bundle loads; meta CSP equal to index.html's (csp.test). Tests: `server/__tests__/passwordResetRoute.test.js`, `client/src/reset/resetPage.test.js`, adminCore

## Account deletion

- Account deletion (`authHandlers.deleteAccount`) requires an authenticated socket + password re-confirm; it runs the shared `server/admin/accountDelete.js` deletion (the admin panel's too: see Admin panel): deletes the user document with both stats buckets (`stats`, `botStats`), anonymizes the username in `gameRecords` (`teamNPlayers` only; the bot personas in `teamNBots` stay), cleans block lists and reset links, keeps reports marked deleted, deletes its tombstones

## Account Admin (owner-run, against production via `MONGO_URI`)

```bash
node scripts/merge-accounts.js --find-duplicates                  # list look-alike usernames
node scripts/merge-accounts.js --into Alan alan2 AlanB            # dry run: prints every change
node scripts/merge-accounts.js --into Alan alan2 AlanB --apply    # asks you to type MERGE
node scripts/set-password.js Alan                                 # new friendly password, signs out all devices
node scripts/set-admin.js --list                                  # read-only: who is an admin (run this first)
node scripts/set-admin.js Alan                                    # lists admins, then asks you to type ADMIN
node scripts/set-admin.js Alan --remove                           # lists admins, then asks you to type REMOVE
node scripts/avatar-report.js [--list]                            # read-only: stored custom pictures, sizes, how many derive (run before enabling the avatar pipeline)
```

Merging is idempotent (re-running prints "Nothing to do") and refuses while a source account is in an active game or tournament (and refuses an admin source). Production admin scripts are the OWNER's call: run the read-only listing first (`--list`, `--find-duplicates`, the merge dry run), check the `Database:` line, then apply. The server and these scripts ALWAYS use the `babonline` database: a database name in MONGO_URI's path is ignored (`server/database.js` dbName, `server/admin/cli.js` DB_NAME), and the `Database:` line says so (`describeTarget`: server without path + "(database babonline)"). So a local live check with `MONGO_URI=.../bab-something` still writes the local `babonline` database; isolate a check by pointing MONGO_URI at a separate mongod (another port), not another db name. `set-admin.js` refuses unknown and merged names; the first admin is made this way, the rest from the web panel. No email is stored, so a password reset is either this CLI (a password the owner tells the player) or, from the web admin panel, a one-time link the owner texts (Important Implementation Details: Admin panel, Password reset links).
