## iOS reconnect after a background

- iOS reconnect after a background (owner 2026-11-12, "buttons aren't responsive ... after it supposedly is reconnected"): Socket.IO-Client-Swift 16.1.1, once reconnecting, schedules its next attempt after every connect (`_tryReconnect`: 1.5^n s with jitter, at most `reconnectWaitMax` 5 s) whether or not that handshake answered, and nothing can fire or cancel the tick. So (a) a foreground between two attempts (manager `.notConnected`, socket `.connecting`: a deploy or a network drop during the ~30 s keep-alive) waited up to 5 s for the tick with nothing in flight, and (b) on a slow link (a polling handshake over ~1.5 s) a tick starts a second handshake on the same engine beside the first, and the late answer to the first can be taken for the second, losing the namespace connect (no `.connect`, no restore; read from the library source, not reproduced with a 2.5 s server-side handshake delay) until the server drops the engine (connectTimeout: 45 s by default, now 10 s, `serverOptions.js` above). `SocketManager.reconnect()` and the old namespace leave + join go through the same ticks. `SocketService.forceReconnect` (foreground after the keep-alive, or inside it while not connected; sign-out) therefore never reconnects the old manager: it retires it (`retire`: handlers removed, `reconnects = false`, `disconnect()` so its pending tick returns, socket removed so a late handshake answer joins no namespace) and builds a new manager + socket (`makeConnection`, this service's handlers + `eventRouter.registerAll()`), whose one handshake starts at once with no tick scheduled. The library still overlaps handshakes in its OWN reconnects on a slow link (a deploy while the app is in front); the server's 10 s connectTimeout bounds that. `isConnected` and `isSessionReady` go false on any non-connected `statusChange` (a library reconnect sends no `.disconnect`). Session gate: `.connect` fires before the restore answers, and a New Game tapped in that window made a lobby that the restore's `joinMainRoom` then left (`mainRoomHandlers.joinMainRoom` from a socket in a lobby runs the Leave flow: `leftLobby` + `mainRoomJoined`, `lobbyPlayerLeft` to the others, kept as the safety net for 1.1.0 / 1.2.0; `joinMainRoomInLobby.test.js`), so `SocketService.isSessionReady` is false from every `.connect` until sign-in / sign-up / the restore succeeded and its follow-up emit went out (`noteSessionEstablished`; per-socket order puts a later tap behind it), and the main room's New Game, Tournament, Join and Spectate are disabled until then (fixture `-uiSessionPending YES`). Tests: `ForegroundReconnectTests` (a real manager mid-backoff against a refused local port), `SessionPendingTests` (UI). Ships with the next iOS build
- (`serverOptions.js`: `server/CLAUDE.md`, Key Architecture Patterns.)

## iOS Stats sheet

- Stats sheet (owner 2026-11-13, "you can see records but this isn't visible in the ios app"; ships with the next iOS build): the main room's Stats opens `StatsView` (navigation title "Stats", a segmented Leaderboard / Records control, the system close button; the tab, the leaderboard's sort and expanded rows and the Records period are kept for the session on the states (`LeaderboardState.tab/sort/expanded`, `RecordsState.period`; the sheet rebuilds a tab's view on every switch), never on disk). Leaderboard = the web LeaderboardPage: `LeaderboardColumn` (the web's eight columns, labels, formats and `defaultAscending`), `LeaderboardSort` (Win % descending first, the sorted column flips, another column takes its preferred direction, stable on ties; the population row sorts by its averages and is never ranked), avatars from `avatarUrls` (clientHello cap) else the stock number through `AvatarImageView`; the eight-column table with pinned sortable headers where it fits (iPad, type <= xxxLarge; the header row has the rows' insets, so each label sits over its column, and is all caps like the web's), else a list with a Sort menu + order button (pinned, except at accessibility sizes, where it scrolls away with the rows) whose rows expand to every column (phones, the Duo, accessibility sizes stack the stats under the name). Records = the web RecordsPage (`GameRecords`, `RecordRow`: total line, All Time / This Year / This Month cards, the same labels, tones and lines, "No games yet"), one to three cards across; where one fits across at standard type sizes (phones, the closed Duo) an All Time / This Year / This Month segmented control shows one card at a time (accessibility sizes stack the three). Requests (`StatsLoader`: `LeaderboardState`, `RecordsState`; `LeaderboardEmitter.getLeaderboard/getRecords`, `Leaderboard/RecordsSocketHandler`): sent on each tab's appear and on pull to refresh, one in flight, 10 s timeout, a failed refresh keeps the last data under a Retry banner, the server's soft-limit reply ("Too many requests") is its own state; records loaded in an earlier month are dropped before the next request (This Month is the server's month). Every reply field is optional (`StatsWire`: numbers, numeric strings, no booleans; a row without a username is dropped). Stats scope (server 2026-11-13): iOS sends `getLeaderboard`/`getRecords` with no payload, so it always gets the human-games bucket and the replies carry no `scope` echo (byte-identical to before); the decoders read keys one by one through JSONSerialization and ignore unknown keys, so an echo would be harmless anyway. A scope picker is a BACKLOG item (iOS: other). Tests: `StatsTests` (unit), `StatsUITests` (`-uiStats`, README "UI tests")

## iOS project

- iOS project (README "iOS project layout" / "Adding test targets"): the committed `iOSClient/BABOnline.xcodeproj` is the single source of truth (team 9SYNY7K2HE, bundle id, versions, entitlements, INFOPLIST_KEY_*, SPM packages). There is no XcodeGen spec, so never add one or regenerate the project. It uses Xcode 16 synchronized folders (`objectVersion = 77`, one `PBXFileSystemSynchronizedRootGroup` for `BABOnline/`), so a new .swift file or folder under `iOSClient/BABOnline/` is compiled with no pbxproj edit. Any other file there is copied into the app bundle, so keep non-app files outside it (e.g. `iOSClient/generate_icon.swift`). `Info.plist` and `BABOnline.entitlements` stay in the folder's `membershipExceptions`, so they are never bundle resources. `PrivacyInfo.xcprivacy` there is bundled on purpose (the privacy manifest). Versions live only in the project (`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`; Info.plist reads them) and export compliance is answered in Info.plist (`ITSAppUsesNonExemptEncryption` NO); release steps in README "Releasing (App Store)". 1.2.0 (6) is the App Store build (live 2026-11-13; 1.1.0 (2) was live from 2026-11-11); the old 1.0.0 (1) and 1.1.0 (2) builds see only an update message (`server/socket/upgradeGate.js`, MIN_IOS_BUILD 3); 1.2.1 (7) is the next release (MARKETING_VERSION 1.2.1: the 1.2.0 train closed when build 6 was released; build 7 adds removing lobby bots, game-end stats, the Stats sheet with Records and the four-suit empty lobby) (build 3 was uploaded but never submitted; build 4 adds my pips in my seat's row and HSI in the bid panel, docs/ios-table-store.md "iOS 1.2.0"; build 4 was pulled from review and never ships; build 5 replaced it: one Exit label (its arrow points left, also in the Duo vertical bar: `ExitIcon.barImage`, since the bar ignores `.scaleEffect`), the leave alert, the iPad table size, the background-resume fix, the Draw for Deal refresh, and it reads positionUpdate.isBot with the bot: socket prefix as the fallback; build 6 = build 5 + the new app icon (a fanned hand: spade, heart, joker star; light, dark and tinted appearances from `iOSClient/generate_icon.swift`, the web icons from it via `npm run build:icons`), approved and live 2026-11-13, so it reads exactly what build 5 reads (`iOSClient/` at 92d0c75); build 7 = build 6 + removing a lobby bot that is not ready with Ready following the server's list (#249), the per-player stats on the game-end screen (#250) and the Stats sheet with Records and a leaderboard at web parity (#252); it sends `clientHello {caps:['avatarUrl']}`, listens to `serverError`, maps voice peers by username; what it unblocks: V1_REMOVALS "What iOS 1.2.0 unblocks").
