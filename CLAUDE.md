# BAB Online - Claude Context Document

This document helps Claude understand the project quickly in new sessions.

## What is this?

BAB Online is a 4-player online multiplayer trick-taking card game ("Back Alley Bridge"). Players form 2 teams (positions 1&3 vs 2&4) and compete across 13 hands with varying card counts.

**See `docs/RULES.md` for complete game rules.**

## Tech Stack

- **Frontend (web)**: Phaser 3.55.2 (game engine), ES6 modules, Socket.IO client 4.8.1 (the server's version), Vite bundler; both libraries are bundled (`client/src/vendor.js`, `client/src/socket/createSocket.js`), no CDN scripts
- **iOS**: Native SwiftUI app in `iOSClient/` (SpriteKit game scene, Socket.IO-Client-Swift, WebRTC voice) — NOT a webview; it mirrors the web client's socket contract
- **Backend**: Node.js 18+, Express.js, Socket.IO server
- **Database**: MongoDB (native client, no ORM) — collections: `users`, `gameRecords`, `reports`
- **Testing**: Jest (server), Vitest (client)
- **Deployment**: Railway via its GitHub integration on push to main (GitHub Actions runs tests/build only)

## Key Architecture Patterns

**Server:**
- `GameManager` singleton manages all active games and queue
- `GameState` encapsulates all state for a single game
- `rules.js` contains pure, stateless game logic functions (highly testable)
- Socket handlers wrapped with validation, rate limiting, error handling

**Client:**
- `GameState` singleton replaces global variables
- `SocketManager` tracks listeners for cleanup (prevents memory leaks); after a background > 5 s it pings (requestSnapshot) and forces a reconnect only when the ping goes unanswered
- `ClientSession` (`client/src/state/ClientSession.js`) is the one owner of the screen (FSM BOOT/SIGN_IN/MAIN_ROOM/LOBBY/TOURNAMENT_LOBBY/TABLE(role)/GAME_END, explicit transition table; illegal → logs and fails closed, throws under Vitest; UIManager.showScreen goes through it), the table role, every gameId copy and the reconnect order: every connect restores the session first, then one rejoinGame per socket / re-spectate / re-enter the screen. The table is entered only via `enterTable(role, gameId)` and left only via `exitTable(reason)` (main.js `teardownTableUI` is its teardown; tournament players route back with returnToTournament). A restore records the server's `activeTournamentId` before any rejoin, so a failed rejoin returns to the tournament; a tab that only watches a tournament keeps `tournamentSpectate` in sessionStorage (a reload re-spectates, never `joinTournament`; its lobby shows no player controls; leaving a table it watched goes back to watching: `spectateTournament` from a socket the server does not know as the tournament's spectator, else `returnToTournament`). Deferred table rebuilds stop on a newer `tableGeneration` (each rejoinSuccess bumps it) or when the screen is no longer TABLE. GameState splits session identity (username, tournamentId — survive `reset()`; `resetSession()` clears them) from per-game state. Page-level tests: `client/src/sessionFlows.test.js`, `client/src/reload/*.test.js` (harness `client/src/testing/fakePage.js`)
- Manager pattern: specialized managers (CardManager, TrickManager, etc.)
- Client-side validation mirrors server for immediate UI feedback

## Key Data Structures

**Card:**
```javascript
{ suit: 'spades'|'hearts'|'diamonds'|'clubs'|'joker', rank: '2'-'A'|'HI'|'LO' }
```

**Server GameState:**
- `seats`: {1..4 → seat record} (`server/game/SeatState.js`): who controls the seat and whether its owner is present (see Important Implementation Details)
- `players`: Map<seat socketId → {username, position, pic}> and `positions`: {pos → seat socketId} — a derived index of `seats` (display identity: the owner for a human seat, else the bot), written only by the seat transitions
- `entrants`: Map<socketId → {username, isBot, presence connected|disconnected|left}> before seating (set by `createGame`, null once 4 seats exist)
- `hands`: {socketId → card[]}, `bids`: {position → bid_value} during bidding, then {team1, team2}
- `stage` (internal, authoritative): `CREATED → DRAWING → DRAW_RESOLVING → TEAMS_ANNOUNCED → (DEALING → BIDDING [→ REDEAL → DEALING → BIDDING] → PLAYING ⇄ TRICK_RESOLVING → HAND_RESOLVING) ×13 → ENDED`, any live stage `→ ABORTED` (`server/game/GamePhase.js`). `epoch` bumps once on ENDED/ABORTED
- `phase` / `bidding`: read-only wire projections of `stage` — `phase` is 'waiting'|'drawing'|'bidding' (never 'playing'; it stays 'bidding' through play), `bidding` is false only from the end of bidding to the next deal
- `trump`: card, `isTrumpBroken`: boolean
- `playedCards`: [pos1Card, pos2Card, pos3Card, pos4Card]
- `tricks`: {team1: count, team2: count}

**Bid Values:** '0'-'13' for numbers (a number may not exceed the hand size, so '13' only on the 13-card hand: owner 2026-11-11, "technically legal, just very unlikely"; a plain 1x bid of 13 tricks), 'B'/'2B'/'3B'/'4B' for bores (2x/4x/8x/16x multipliers). `rules.BID_VALUES` is the one list (the Joi `playerBid` schema and `GameState.validateBid` use it / `isValidBid`); Joi takes '13'/13 on any hand and `isValidBid` refuses it below 13 cards (`actionRejected invalid_bid`). For the lead every bore outranks a numeric 13 (`findHighestBidder`); bots never bid 13 (`server/socket/__tests__/bid13.test.js`)

## Game Flow (Socket Events)

1. **Auth**: `signIn`/`signUp` → `signInResponse` (includes `blockedUsers`; `deleteAccount` → `deleteAccountResponse` for in-app account deletion); `restoreSession` resumes a saved per-device token without a password
2. **Lobby**: `joinQueue` → `lobbyCreated` → `playerReadyUpdate` → `allPlayersReady`
3. **Draw**: `startDraw` → `draw` → `playerDrew` → `teamsAnnounced`
4. **Bidding**: `gameStart` → `updateTurn` → `playerBid` → `bidReceived` → `doneBidding` (if both teams bid 0 there is no `doneBidding`: the server sends a log entry, `destroyHands` and a fresh `gameStart` for the redeal)
5. **Play**: `updateTurn` → `playCard` → `cardPlayed` → `trickComplete` → `handComplete`
6. **End**: `gameEnd` (payload always includes `tournamentId`, null for casual games)
7. **Resync (snapshot v2)**: `requestSnapshot {requestId?, customPics?, log?}` → `stateSnapshot {snapshot, requestId?}` or `{snapshot: null, reason: 'not_in_game'}` (any seat owner, entrant or spectator; custom pictures only with `customPics: true`; `snapshot.partial` lists what was left out and the client keeps it — `mergeSnapshot`; `seq` on room broadcasts tells a v2 client when it missed something)

**Tournaments**: `createTournament`/`joinTournament` → `tournamentJoined` → ready-up → `beginTournament` → 4 rounds of games (`tournamentGameAssignment`, results via `tournamentGameComplete`/`tournamentRoundComplete`) → `beginNextRound` between rounds → `tournamentComplete` (with `winners[]`). The creator may cancel in any phase (`cancelTournament` → `abortGame` at every running table, then `tournamentCancelled`). Disconnected players are marked `connected: false` and reattach by username (any phase); completed tournaments linger ~10 min so players can view results.

**Safety**: `reportUser` → `reportUserResponse` (stored in `reports` collection); `blockUser`/`unblockUser` → `blockListUpdated`. Chat is profanity-filtered server-side; clients hide blocked users' messages.

## Quick Game Rules Reference

- 54 cards (52 + HI/LO jokers), jokers are always trump
- Hand sizes: 12→10→8→6→4→2→1→3→5→7→9→11→13
- Must follow suit; trump can't lead until broken (unless hand is all trump)
- HI joker forces opponents to play highest trump, partner plays lowest
- Scoring: Made bid = (bid × 10 × multiplier) + overtricks; Set = -(bid × 10 × multiplier)
- Rainbow bonus: +10 on 4-card hand if hand has all 4 suits

## Important Implementation Details

- Game phase FSM (`server/game/GamePhase.js`, `GameState`): the stage changes only through `game.transition(from, to)` (every call site reads `if (!game.transition(F, T)) return;` — an illegal call throws under Jest / `BAB_FSM_STRICT=1`, logs and fails closed in production), `tryTransition` (the DRAWING → DRAW_RESOLVING latch, so the draw resolves exactly once) and `terminate(io, ENDED|ABORTED, event, payload)` (final event out first, then epoch bump + cancel all game timers). Never write `game.phase`/`game.bidding` (getters; a write is a reported violation) and never gate on flags — gate on `game.stage` (`acceptsTurnInput()`, `actionTypeForTurn()`, `isPreSeating()`). Lifecycle waits use `if (!(await game.pause(ms))) return;` (presentation holds: `game.hold(kind, ms)`, see Pacing) and timers use `game.setTimer(key, ms, fn)` (`grace:<pos>` per-seat reconnect grace, `abandon`, `draw:watchdog`, `resume` (trick/hand hold); `afk:<pos>` the turn watchdog, see AFK below; bot bid/play/draw/chat stay in `BotController.pendingActions`), so nothing runs or emits after end/abort; BotController timers check `game.epoch`, and `broadcast`/`sendToPlayer` drop everything from a terminal game. `recordDraw` is the only writer of draw state. Abort only through `socket/gameLifecycle.abortGame(io, game, reason)` (abortGame to the room incl. spectators → ABORTED → `GameManager._retire`: bots, room, every `playerGames` entry for the game → lobbiesUpdated → DB/tournament follow-up); the draw starts only through `gameLifecycle.beginDraw` (also auto-draws for sockets that left/disconnected during the pre-draw countdown). The end path sends `gameEnd` before persisting stats. Jest's `server/testUtils/fsmGuard.js` fails any test that records a violation; `BAB_FSM_CHECK=1` runs `validateGameState()` (per-stage + seat invariants) on every stage and seat transition and records `_history` (`server/socket/__tests__/chaos.test.js`, `lifecycle.test.js`, `wireProjection.test.js`)
- Pacing (`server/game/pacing.js`, the only home of presentation delays; read `pacing(game).X` at call time, never destructure): profiles `standard` (default), `legacy` (pre-retune values, rollback knob), `fast` (dev only, ignored in production), `zero` (tests only) via `BAB_PACING`; bot ranges are `[min, span]` with ONE `Math.random()` per action (`BotPlayer.getActionDelay(type, {kind})`; `BotController.actionKind` picks firstBid/bid, afterBidding/afterTrick/forced/follow at schedule time from public state only — forced = the hand's last card, never "one legal card", which would leak a void; leads never use the forced range). `SHIPPED_IOS_FLOORS` is what the App Store build (1.1.0 build 2, iOS source f05d264) needs — it decodes but never reads resumeInMs and animates on receipt, so the server's gaps are still what it gets; unlike 1.0.0 it rolls a refused action back (actionRejected) and collects a trick in its own layer (no guarded clearTrick), so its floors are lower: BOT_FIRST_BID 500, BOT_LEAD_AFTER_BIDDING 300, BOT_LEAD_AFTER_TRICK 400, HAND_END_MS 400 (the rest unchanged; evidence in pacing.js). `pacing.test.js` holds every non-zero profile to it, and standard + legacy also to `IOS_1_0_FLOORS` (the old build's floors) because `UPGRADE_GATE=off` lets 1.0.0 play again; `pacingBudget.test.js` checks every gap against the larger of the two. The standard values are unchanged (owner, 2026-11-11: no pacing change yet); lowering them toward the 1.1.0 floors is a separate owner decision (BOT_LEAD_AFTER_TRICK also has the web collect's 500 ms floor). Retune: edit the profile, run `BAB_PACING_REPORT=1 npx jest server/socket/__tests__/pacingBudget.test.js` (1 human acting instantly + 3 bots over 12 seeds: legacy 594.6 s, standard 320.9 s; sensitivities in the pacing.js header; TRICK_VIEW_MS is the cheapest knob, 1000 gives about -48%; `legacy` also skips the ambient pre-game overlay) and repin its component table. Holds: `game.hold(kind, ms)` for linear chains (countdown, drawReveal, seating, teams, firstTurn) and `game.scheduleResume(kind, ms, fn)` on the `resume` timer for TRICK_RESOLVING/HAND_RESOLVING: the 4th card returns at once, `resumeTrick` counts the trick at resume (so a rejoin inside the hold sees today's pre-resolution table) and sends trickComplete + updateTurn in the same tick, or holds HAND_RESOLVING until handComplete; `game.resume` = `{kind, at}` while a hold is open (`resumeInfo(now)` → snapshot v2 `resume {kind, inMs}`). Wire: relative `resumeInMs` on the trick-completing cardPlayed, a hand's last trickComplete and teamsAnnounced (contract/README.md "Resume holds"). Early actions inside a hold are rejected (`not_your_turn`), never queued: no compliant client can send one (no updateTurn goes out after the 4th card; the trick winner's updateTurn shares the trickComplete tick and its play is accepted). Web sizes its fly-in/collect/teams fade to resumeInMs and keeps the hand dimmed until the collect lands (`TrickManager.isCollecting/onCollected`; iOS source builds: `SKTrickManager.isCollecting`). Event order is unchanged. Rate limits: playCard 90/min, playerBid 30/min (an over-limit play gets `error`: 1.1.0 shows a toast and resyncs the table (SocketService `clientEvent: .error` → routeTableError); 1.0.0, now gated, lost the card)
- Bots have socketIds like `bot:{username}:{uuid}`, use `BotStrategy.js` for AI. Card play is contract-aware: `processBotPlay` passes a play context (team bids/tricks/bores) into `decideCard`. Personalities (`personalities.js`) define `bidStyle` + `playStyle` consumed by the strategy; Mary is the sim-tuned optimal baseline, the others are slight measured variations. Strategy changes must be benchmarked with `npm run sim` against the frozen legacy snapshot (`sim/legacyStrategy.js`)
- Sessions are per device (`server/utils/sessionTokens.js`): each sign-in adds a token to `users.sessionTokens` (SHA-256 hashes only, max 5, expire 90 days after last use) instead of replacing the old one, so signing in on the computer doesn't log the phone out. A legacy plaintext `users.sessionToken` is still accepted and migrated. Only one *live* socket per user: a password sign-in, or a different device restoring its token, kicks the previous socket (`forceLogout`); the same device reconnecting (same token hash in `socket.data.sessionHash`) does not. `rejoinGame` from an unauthenticated socket (web reload mid-game) is authorized by the same `verifySession` check on the token it sends. Rejoining a tournament game also reattaches tournament membership to the new socket
- Web "stay signed in" (`client/src/utils/sessionPersistence.js`): the tab's session is in `sessionStorage` (so 4-tab local testing still works) and the latest sign-in is mirrored to `localStorage`, which a fresh tab adopts on load. Profile page has a Sign Out button (shared family computers). iOS keeps its token in the Keychain
- Merged accounts: `scripts/merge-accounts.js` turns duplicate accounts into tombstones `{ username, mergedInto, mergedAt }` (no password/tokens/stats). Sign-in/sign-up/restore on a tombstone tell the player which account to use; leaderboard and player search exclude them; `getPlayerProfile` follows `mergedInto`; deleting the kept account deletes its tombstones. The kept account's `mergedFrom[]` is the audit log and the idempotency guard. Any new per-user data keyed by username must be added to `server/admin/accountMerge.js` (in-memory server state keyed by username — the profile caches, the sign-in throttle — cannot see a CLI merge; the caches' 60 s TTL and the throttle's 15 min window bound it)
- Socket rooms: players join `game:{gameId}` for broadcasts; tournaments use `tournament:{tournamentId}`
- Socket contract (`contract/`, dev/test only — production code never requires it; see `contract/README.md`): `contract/src` describes every event in both directions (payload JSON Schema, status, emittedFrom, clientReads, reserved keys); `npm run contract:gen` writes `contract/events.schema.json`, `client/src/constants/events.js` and `iOSClient/.../Constants/SocketEvents.swift` (from `contract/layout.json`; never hand-edit them; `generated.test.js` fails when stale). Every emit recorded through `gameDriver.makeIo`/`makeSocket` is validated by the always-on contract guard (`server/testUtils/contractCheck.js` + `contractGuard.js`; escape hatches `contractGuard.skip(reason)` / `BAB_CONTRACT=0`). **The wire is still additive-only**: 1.1.0 is the App Store build and 1.0.0 is gated (owner decision 2026-11-11), so the removals in `contract/V1_REMOVALS.md` may now proceed one PR at a time in the order of its plan (each one ends UPGRADE_GATE=off as a full rollback); until a removal PR says otherwise, never rename/remove an event or change a field's type/meaning/order — `additiveOnly.test.js` holds the schema to the frozen `contract/v1-baseline.schema.json`, `legacyConstants.test.js` pins every cc865b4 constant, `wireCompat.test.js` pins the values of the touched builders. The non-additive changes wait in `contract/V1_REMOVALS.md`
- Snapshot v2 (`server/game/snapshotV2.js`, `game.getSnapshotV2(sid)`; `$defs.snapshotV2`): one normalized, versioned table view for the receiving socket (stage, viewer role, hand, bids, trick in play order, seats from the seat records, draw/entrants, tournament; no socket ids). Sent as an extra `snapshot` field on rejoinSuccess / restorePlayerState / actionRejected / the spectator full state and as the reply to `requestSnapshot`. Fixtures in `contract/fixtures/v2` (`npm run contract:fixtures`), web parser `client/src/state/snapshotV2.js`
- Web table (item 16): `client/src/state/GameState.js` is the ONE writer of table state: `handlers/gameHandlers.js` applies each event (`applyDeal/applyBid/applyCardPlayed/applyTrickComplete`...; trick counts and trumpBroken live there, never in the scene; playerLazyMode/playerActiveMode/playerResigned write the seat's name and picture with `applySeatDisplay`, so a re-render keeps the bot) and every snapshot goes through `state/tableSync.applyTableSnapshot` (parse v2, else `state/legacySnapshot.js` from the v1 fields → `GameState.applySnapshot` → `MyAction.reconcile` → render → `SeqGate.onSnapshot`). `state/SeqGate.js` (R1-R5) wraps every SocketManager listener (`setGate` before the handler modules register): a gap buffers and sends `requestSnapshot {requestId:'gap-N', log:false, customPics:false}`, the reply replays what is above S; baselines reset at startDraw / another gameId's gameStart / gameEnd / abortGame. `GameScene.render(model)` (model = `GameState.renderModel()`, snapshot shaped) clears every manager and draws the table idempotently (opponent backs from `seatCards`, trump face up, stacks from the hand's own history or face-down placeholders); main.js `renderTable` adds the log (replaced with a DocumentFragment from `snapshot.log` unless `partial` has 'log'), header, indicators, pill. `phaser/TableDirector.js` owns every delayedCall/tween (managers use `sceneDelay`/`sceneTween`), keyed {gameId, handNo, deal, trickNo} (scope 'deal'/'trick' work skips a later key; `reset()` cancels all, render calls it), buffers scene work until GameScene has its managers (`run`, by tableGeneration; a late flush ends with one render), gates the first deal on the createUI fade (`uiReady`) and later deals on the trick whisk (`afterTransition`; a play during the wait `settleDeal`s), and fast-forwards (cancel + render) when a hidden tab comes back with anything changed or in flight. No window flags/events (`_transitionOverlay`, `_readyForGameUI`, `_tricksAnimating`, trumpFlipComplete/gameUIReady/tricksCleared are gone; `ui/transitionOverlay.js` keeps the overlay handle). `state/MyAction.js`: one pending bid/play (idle → pending → confirmed by my own cardPlayed/bidReceived, or rolled back by actionRejected's snapshot); a click never edits GameState (renderModel hides the pending card); after 5 s without an answer `requestSnapshot 'ack-N'` and reconcile (card gone from the hand = accepted; a 'gap-'/'ping-' reply, whose request may predate the action, that still shows my turn keeps it pending), a second silence forces a reconnect, never a blind rollback; a click on a disconnected socket is ignored. Tests: `client/src/table/*.test.js` run the real GameScene/managers on `testing/fakePhaser.js` and replay the recorded games in `iOSClient/BABOnlineTests/Fixtures/events` (read only) and `contract/fixtures/v2` (`testing/replay.js`: counts vs every checkpoint snapshot, rejoin on a live scene vs a fresh render)
- Web table layout (item 17): `client/src/phaser/layout/computeTableLayout.js` is the ONE source of table geometry, a pure function of the canvas size (`{w, h, dpr, isSpectator, logW}`): one size scale `s` (<= 1) for every sprite and DOM size, SOLVED by searching s (and the trick history's own 1 / 0.85 / 0.7 step, a roomy then a compact hand box) for the first layout with no rect intersections and nothing off the canvas, checked by the same `findIntersections` / `findOutside` the tests use; positions are today's fractions of the canvas where they fit (1920x1080 keeps the old table). It returns per seat (self, partner, opp1, opp2; a spectator's self is the bottom seat) the avatar, plate, card fan, bubble and dealer anchors, the trick slots and play zone, both history blocks (13 slots each), the hand box, trump, the felt (today's 0.3125 x 0.42 of the window where the side seats can move out for it, tried after s is solved) and the bid sheet inside it (it may cover only the empty trick), each seat's bubble direction and max width (at its largest, 3 lines, it never covers the trump, hand, trick slots, histories or another bubble: `BUBBLE_KEEPS` in the same check), status pill, voice slot, draw-phase deck/slots/title, teams overlay and effects. ## Account Admin (owner-run, against production via `MONGO_URI`)

```bash
node scripts/merge-accounts.js --find-duplicates                  # list look-alike usernames
node scripts/merge-accounts.js --into Alan alan2 AlanB            # dry run: prints every change
node scripts/merge-accounts.js --into Alan alan2 AlanB --apply    # asks you to type MERGE
node scripts/set-password.js Alan                                 # new friendly password, signs out all devices
node scripts/avatar-report.js [--list]                            # read-only: stored custom pictures, sizes, how many derive (run before enabling the avatar pipeline)
```

Merging is idempotent (re-running prints "Nothing to do") and refuses while a source account is in an active game or tournament. There is no in-app password reset by design (no emails are stored); the owner resets passwords for players who ask.
