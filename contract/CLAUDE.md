# Socket contract, snapshot v2, seq and the upgrade gate

Loads automatically when Claude reads a file under `contract/`; the full rules are `contract/README.md` and the removal plan is `contract/V1_REMOVALS.md`. Open this file before ANY change to an event or payload, from server, web or iOS.

## Socket contract

- Socket contract (`contract/`, dev/test only — production code never requires it; see `contract/README.md`): `contract/src` describes every event in both directions (payload JSON Schema, status, emittedFrom, clientReads, reserved keys); `npm run contract:gen` writes `contract/events.schema.json`, `client/src/constants/events.js` and `iOSClient/.../Constants/SocketEvents.swift` (from `contract/layout.json`; never hand-edit them; `generated.test.js` fails when stale). Every emit recorded through `gameDriver.makeIo`/`makeSocket` is validated by the always-on contract guard (`server/testUtils/contractCheck.js` + `contractGuard.js`; escape hatches `contractGuard.skip(reason)` / `BAB_CONTRACT=0`). **The wire is still additive-only**: 1.0.0 is gated (owner decision 2026-11-11) and, since MIN_IOS_BUILD 3 (owner: once 1.2.0 is live), 1.1.0 too, so the removals in `contract/V1_REMOVALS.md` may now proceed one PR at a time in the order of its plan (each one ends UPGRADE_GATE=off as a full rollback; the plan's "safe now" steps ran 2026-11-11: #15, #16, #2, #4, #12, #10, #11, #13, #18 and #1 phase A; #20 ran 2026-11-12, one day after the TURN deploy; #1 phase B (app-level `error` dropped, `serverError` alone) is stacked on the MIN_IOS_BUILD 3 gate; #14 ran 2026-11-12 except `positionUpdate.sockets` (`positionUpdate.isBot[]` added; iOS 1.2.0 build 5 reads isBot first and the sockets only as fallbacks after isBot / the username, so dropping them waits only on TestFlight builds 3-4, which read just the `bot:` prefix and have no frozen baseline: V1_REMOVALS #14; `contract/lib/decodeRules.js` `DECODE_RELIED` keeps isBot required and non-null for builds 6-8, whose baselines predate it); #17 was kept by the owner); until a removal PR says otherwise, never rename/remove an event or change a field's type/meaning/order — `additiveOnly.test.js` holds the schema to the frozen `contract/v1-baseline.schema.json` and to one frozen baseline per iOS build that is not gated (`contract/baselines/`: the contract each build was cut from, plus the decode floor read from its Swift; a failure names the build, e.g. iOS 1.2.0 (6)), `legacyConstants.test.js` pins every cc865b4 constant, `wireCompat.test.js` pins the values of the touched builders. The non-additive changes wait in `contract/V1_REMOVALS.md`

## Snapshot v2

- Snapshot v2 (`server/game/snapshotV2.js`, `game.getSnapshotV2(sid)`; `$defs.snapshotV2`): one normalized, versioned table view for the receiving socket (stage, viewer role, hand, bids, trick in play order, `trickHistory` = this deal's won tricks with their cards (additive 2026-11-11; `game.trickHistory`, pushed in `resumeTrick` with the count, reset in `resetForNewHand`; web restores face-up stacks from it), `watching` {spectators, count} = who is watching (additive 2026-11-11, see Spectator badge), seats from the seat records, draw/entrants, tournament; no socket ids). Sent as an extra `snapshot` field on rejoinSuccess / restorePlayerState / actionRejected / the spectator full state and as the reply to `requestSnapshot`. Fixtures in `contract/fixtures/v2` (`npm run contract:fixtures`), web parser `client/src/state/snapshotV2.js`. A snapshot a client cannot read: the web rejects `v` other than 2; iOS 1.2.1 build 9 and earlier decode the generated `TableSnapshot` strictly (every required key, `trickHistory` and `watching` included) and, when a resync's answer fails, freeze on that table; from the next iOS build a snapshot that is undecodable, not v 2 or of an unknown stage is retried twice and then shows "update the app" with Leave (`docs/ios-table-store.md`, "Snapshots this build cannot show"). So never drop or retype a snapshot key while those builds are in use, and add new keys as optional (`obj(..., { optional })`, which the Swift generator makes Optional). `bidClock` (2026-11-18) is the one key present only while it applies (a running bid clock): the exception to "every key always present"
- (Spectator badge: `docs/claude/spectators.md`.)

## seq

- `seq`: `game.eventSeq` +1 per room broadcast (`GameState.broadcast` stamps `{...data, seq}`) and +1 per deal (every gameStart of a deal carries the same value); private emits carry none, and neither do the three UNSEQUENCED room events, `spectatorsUpdated`, `bidClock` and `seatLeft` (schema `seq: false`, `GameState.emitUnsequenced`; the contract guard checks both rules; contract/README.md "Bid clock"). Consumer rules R1–R5 in `contract/README.md`; `server/testUtils/seqCheck.js` checks them per receiver in chaos and contract tests

## Upgrade gate

- Upgrade gate (`server/socket/upgradeGate.js`, owner decision 2026-11-11; MIN_IOS_BUILD 3 once 1.2.0 is live, owner decision 2026-11-12): the old App Store builds 1.0.0 (cc9059f, build 1) and 1.1.0 (f05d264, build 2) get an update message on every screen they can be on and nothing else. Detection is the handshake User-Agent only, positive identification, fail open: URLSession's `BAB%20Online/<CFBundleVersion> CFNetwork/<v> Darwin/<v>` from the polling handshake (every iOS build polls first; Starscream's websocket upgrade sends no User-Agent, and socket.handshake keeps the polling headers); gated only when that parses with build < 3 (`MIN_IOS_BUILD`). Browsers, a missing/garbled/dotted User-Agent and builds >= 3 (1.2.0 build 6 is the App Store build, live 2026-11-13, and reads what build 5 read; 3 was never submitted and 4 was pulled from review; 1.2.1 (7) is on TestFlight and 1.2.1 (8) is the next build) are never gated; `clientHello` is not the signal (1.0.0 and 1.1.0 never send it). A gated socket registers NO handler from setupSocketHandlers (never signs in, never online, never in a room/lobby/game); its only DB touch is on its first restoreSession: for a token `verifySession` accepts it sets that one `sessionTokens` entry's `lastUsedAt` to now (arrayFilters `$set`; no socketId, no registerUser), because sessions expire 90 days after last use and before the gate every launch of an old build refreshed it (a token not accepted: the later messages drop "You'll stay signed in"). It gets `signInResponse {success:false, message}` (shown in red under the password on SignInView and RegisterView, whose onAppear both clear it; never `restoreSessionResponse`, whose failure clears the app's saved token, so the update finds the player signed in: every build uses the Keychain service `com.bab-online.auth` with the same accounts) pushed 0.3 / 2 / 5 s after connect, then every 6 s while connected (`REPEAT_MS`; switching Sign In / Register sends nothing, so this puts the message back), and as the reply to restoreSession / signIn, `signUpResponse` to signUp, an update-only `mainRoomJoined` (no lobbies/games, one chat line) at 2 s and on joinMainRoom (a warm reconnect after a deploy lands on the main room; 1.1.0 reads `recentMessages ?? messages`, both carry the line), and leftGame / leftLobby / tournamentLeft for the app's Leave buttons (`/leave`, leaveLobby, leaveTournament, returnToTournament; also leftGame for Tap to Draw's `draw`, since 1.1.0's Leave cannot be reached during the draw: on phones DrawPhaseView's full-screen overlay covers the corner Leave, which stays enabled, and only the Duo's vertical-bar `leaveBarButton` is `.disabled(phase == .draw)`, so re-check reachability, not the modifier, when raising the floor; 1.1.0 then sends joinMainRoom, or returnToTournament after a tournament game's leftGame), so every screen leads to the message; at most 20 emits per socket per minute, the timed pushes stopping at 14 so replies always have room. Kill switch `UPGRADE_GATE=off` (false/0/disabled/no; read per connection). Telemetry: `iOS app connected {build}` (info) for every iOS socket (`socket.data.appBuild`, the adoption count clientHello cannot give for iOS) and one `Upgrade gate: outdated iOS app {build, username, savedSession}` per gated connection (a socket the app replaced at once with no username: debug). Tests: `server/socket/__tests__/upgradeGate.test.js` (captured simulator User-Agents, the build 2/3 boundary, every gated-socket test for both old builds, browsers, garbage, a real Socket.IO server through upgrade and reconnect)
