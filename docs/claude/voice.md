# Voice: signaling, TURN and web keys

Never auto-loaded: open it for `server/socket/voiceHandlers.js`, `server/voice/` (incl. `gameVoice.js` and `tournamentVoice.js`), `client/src/voice/` (including the `voiceHotkeys.js` overlay / mute keys and `voiceCompany.js`, no voice alone), `client/src/ui/components/VoiceChatUI.js` or the iOS `Voice/` code.

## Voice signaling

- Voice signaling (`server/socket/voiceHandlers.js`; roadmap 30's security part, 2026-11-11): voiceOffer / voiceAnswer / voiceIceCandidate are forwarded only when the target is a connected socket id (`io.sockets.sockets`; never a room such as 'mainRoom' or `game:<id>`, never the sender), both sockets are signed in and in the same voice room (`gameVoice.voiceRoomOf`: a lobby (`playerLobbies`), a game (`playerGames`: entrants, seat owners incl. a lazy owner's socket), or, in a casual game, an admitted voice spectator (`game.voiceSpectators`, Spectator voice below), or an admitted member of a tournament's voice room (`tournament:<id>`, Tournament voice below)) — the peers voicePeerList/voicePeerJoined announce; any other pure spectator is refused (a legacy client never starts voice for one) — and neither user blocked the other (`socket.data.blockedUsers`, set by `rememberBlockList` at signIn / restoreSession / signUp / rejoinGame's session-token check and on every blockListUpdated success; a CLI merge is seen at the next sign-in; each side is checked against its own list; a signed-in socket with no list fails closed, refused both ways while `loadBlockList` reads it, with a warning). Per-socket limits checked in-handler (`rateLimiter.limits`: offer/answer 60, ICE 600 per 10 s since 2026-11-16, for a mesh of up to 8 people: 7 peers each; estimates, not measured with TURN), then the payload's Joi schema (`validators.schemas.voiceOffer` etc., V1_REMOVALS #18; the contract's `joiInHandler`: target id <= 64, SDP type + sdp <= 64 KB, candidate fields bounded, nulls and iOS 1.1.0's "" allowed); every refusal is dropped silently (debug log; no reply, never `serverError`, which would toast). A successful `blockUser` between two users who share a voice room (lobby, players, spectators) ends their call: each socket gets a private voicePeerLeft for the other (`gameVoice.endBlockedCall`; before 2026-11-16 an established P2P stream survived a block). Tests: `server/socket/__tests__/voiceSignaling.test.js`, `spectatorVoice.test.js`

## Session mute (owner 2026-11-19)

- Owner: "it defaults to muted now which is great, but when you return back to the lobby at the end of a game to play again it mutes you again - it shouldn't do that, once you unmute in a session it should stay unmuted".
