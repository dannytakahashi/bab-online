# Voice: signaling, TURN and web keys

Never auto-loaded: open it for `server/socket/voiceHandlers.js`, `server/voice/` (incl. `gameVoice.js`, `sdpDirection.js`), `client/src/voice/` (including the `voiceHotkeys.js` overlay / mute keys), `client/src/ui/components/VoiceChatUI.js` or the iOS `Voice/` code.

## Voice signaling

- Voice signaling (`server/socket/voiceHandlers.js`; roadmap 30's security part, 2026-11-11): voiceOffer / voiceAnswer / voiceIceCandidate are forwarded only when the target is a connected socket id (`io.sockets.sockets`; never a room such as 'mainRoom' or `game:<id>`, never the sender), both sockets are signed in and in the same voice room (`gameVoice.voiceRoomOf`: a lobby (`playerLobbies`), a game (`playerGames`: entrants, seat owners incl. a lazy owner's socket), or, in a casual game, an admitted voice spectator (`game.voiceSpectators`, Spectator voice below)) — the peers voicePeerList/voicePeerJoined announce; any other pure spectator is refused (a legacy client never starts voice for one) — and neither user blocked the other (`socket.data.blockedUsers`, set by `rememberBlockList` at signIn / restoreSession / signUp / rejoinGame's session-token check and on every blockListUpdated success; a CLI merge is seen at the next sign-in; each side is checked against its own list; a signed-in socket with no list fails closed, refused both ways while `loadBlockList` reads it, with a warning). Per-socket limits checked in-handler (`rateLimiter.limits`: offer/answer 60, ICE 600 per 10 s since 2026-11-16, for a mesh of up to 8 people: 7 peers each; estimates, not measured with TURN), then the payload's Joi schema (`validators.schemas.voiceOffer` etc., V1_REMOVALS #18; the contract's `joiInHandler`: target id <= 64, SDP type + sdp <= 64 KB, candidate fields bounded, nulls and iOS 1.1.0's "" allowed); every refusal is dropped silently (debug log; no reply, never `serverError`, which would toast). A successful `blockUser` between two users who share a voice room (lobby, players, spectators) ends their call: each socket gets a private voicePeerLeft for the other (`gameVoice.endBlockedCall`; before 2026-11-16 an established P2P stream survived a block). Tests: `server/socket/__tests__/voiceSignaling.test.js`, `spectatorVoice.test.js`

## Spectator voice (family lobbies)

- Spectator voice (owner 2026-11-16: casual lobbies up to 8 people, the first 4 to tap Ready play and the rest watch the game in its text chat and voice; host lobby setting "Spectators can talk", on by default, off = spectators hear but cannot speak; Spectate from the main room joins voice under the same switch; casual games only; per-person mute / volume stay client-side). Only a socket that sent the clientHello cap `casualSpectators` is ever admitted or sent `voiceSettings`: the web bundle sends it since the family-lobbies web PR (web client below); iOS from 1.2.3 build 12 (every shipped iOS build, 1.2.2 build 11 included, is legacy here). `server/voice/gameVoice.js`. State, set only by `GameManager.startGameFromLobby` (so never a tournament table or the ambient demo): `game.casualVoice` {host, spectatorsCanTalk, lastIo, lobbyExtras}, `game.voiceSpectators` (socketId -> {username, order, fromLobby, canTalk, gateSince}), `game.voiceOfferDir` (`s>p` -> last relayed direction); all socket-keyed, cleared in `GameManager._retire` (end and abort). Players side (`gameVoiceMembers`): connected human entrants before seating, then connected owners at their seat (human, or lazy in seat view). Admission (`admitVoiceSpectator`, from `joinAsSpectator`, the lobby start for extras, and the startedLobbies redirect): a casual game, the cap, no other membership (`activityOf`), not a player's other tab (same username in voice), and players holding a slot (entrants not left / owned seats not gone, so a seat in grace keeps it) + voice spectators < 8; a capable socket refused for room gets `voiceSettings {role: 'none'}`; a newer socket of the same user replaces the old entry. A newcomer gets `voicePeerList` (the players, plus the spectators admitted before it while spectators may talk; a pair excluded only by a block list that is LOADED) and offers; the listed peers get `voicePeerJoined`. Who may talk (`mayTalk`): spectatorsCanTalk and (a lobby extra, or a connected capable player exists who could switch it off, owner Q1/Q3: on an all-legacy table a main-room stranger only listens). Who may switch it in game (`canChange`, owner Q3 default): the host while seated, connected and capable, else any connected capable player; `setSpectatorsCanTalk` is coalesced per game (applied at once when nothing changed in the last 3 s, else once at the end of the window with the last value; an unchanged value applies nothing). A change: voicePeerLeft both ways between spectators (off) or a re-announce of the later-admitted ones (on), then `voiceSettings` to every capable socket of the room; the spectator's client switches mode itself and re-offers its calls (a replacement offer keeps mute / volume on web and iOS b10+). SDP gate (`gateSignal`, `server/voice/sdpDirection.js`) in voiceOffer / voiceAnswer: a voice spectator that may not talk is relayed only SDP whose every active audio/video section is recvonly or inactive (media-level a= line, else session-level, else sendrecv; port 0 without bundle-only and m=application ignored; anything unparseable counts as sending); drops logged at debug, a running count at info; players and lobby members are never gated. Backstop: 8 s after a spectator loses the right to talk, every (spectator, player) pair without a listen-only offer/answer from it since then is torn down (private voicePeerLeft both ways) and re-announced, so it offers again (gated). Leaving: every `GameManager.leaveSpectating` (all callers, incl. the io-less disconnect / supersede paths, which use `casualVoice.lastIo`) removes the voice entry and tells the voice peers privately, never the room; a voice spectator becoming an owner (reconnectOwner / reclaimSeat / watchSeat, `seatLifecycle.leaveSpectatingFor`) drops its calls both ways first and then gets the owner peer list (`announceOwnerVoice`, which now also lists the voice spectators and runs for a reclaim too); a demoted owner socket (watchSeat) ends its calls both ways; an entrant dropping or leaving during the draw sends a private voicePeerLeft to the voice peers (every game). `voiceSettings {gameId, host, spectatorsCanTalk, role: player|spectator|none, canTalk, canChange}` (private, unsequenced) goes to capable sockets only: at the start, on admission, on an applied change, when an owner drops / returns / reclaims, when an entrant leaves, and whenever a seat owner leaves the voice room otherwise (/leave via `leaveSeat`, a lazy owner at its seat disconnecting, a watchSeat demotion, /active from the watch view): `gameVoice.refreshVoice` recomputes who controls the switch and who may talk (a main-room spectator whose last capable player left loses canTalk and arms the backstop). Rate limit `setSpectatorsCanTalk` 4 / 30 s. Not device-tested: listen-only playout, a legacy iOS answer to a recvonly replacement offer, the 3 s / 8 s timings. Tests: `server/socket/__tests__/spectatorVoice.test.js`, `familyLobby.test.js`, `server/voice/__tests__/sdpDirection.test.js`
- Spectator voice, web client (2026-11-16; `client/src/voice/VoiceChatManager.js`, `voiceLifecycle.js`, `handlers/voiceHandlers.js` -> main.js `onVoiceSettings`, `ui/components/VoiceChatUI.js`, `SpectatorBadge.js`). Talk mode: one desired field, `_wantTalk`, read by connectToPeer, handleOffer and initialize's flush; listen-only asks for no microphone, offers with `addTransceiver('audio', {direction: 'recvonly'})` (never a null-track sendrecv, whose SDP the gate would drop) and answers without a track; a peer gate is `active`, not a held mic. A refused (or missing) getUserMedia is listen-only, not a failure (`micDenied`; the session starts, flushes what it buffered and hears everyone; "Microphone access denied. You can still listen to voice chat."), so `voiceLifecycle`'s onUnavailable is only for a browser with no WebRTC. `setTalk(bool)`: off stops the mic tracks at once, on asks for the mic (a refusal stays listen-only); a real change re-offers every call (one marked "voice unavailable" too, so the server backstop sees this mode from every pair) `REOFFER_DELAY_MS` (300 ms) later through the restart path (`_closePeer({keepRecovery})` + `connectToPeer`: the other side's handleOffer replaces its call and keeps its mute and volume), a call still in `have-local-offer` only after its answer lands (or its connect timer runs out: a stale answer must never meet the new connection); while voice is starting it only sets the mode (`voiceLifecycle.start({talk})`, a second start hands its mode on through `setMode`), so a voiceSettings during the microphone prompt wins. One volume rule, `_applyVolume` / `_effectiveMuted` = my mute or the forced mute (`setForcedMute(predicate)`), used by ontrack, mute / unmute, setPeerVolume and the noise gate (which used to reset the volume and check only my mute). Autoplay: an element whose `play()` is refused (NotAllowedError) calls `onAutoplayBlocked` ("Click anywhere to hear voice chat.") and the next pointerdown / keydown plays every call's element; a re-created call blocked again re-arms. main.js on `voiceSettings` (a late one for another gameId is ignored): role `spectator` sets the mode to canTalk AND wants-the-mic (a lobby extra arrives with its mic live and keeps wanting it; a main-room spectator wants it only after "Tap to talk", and again after each off -> on, owner Q1), starting voice listen-only when it is not running (no microphone prompt on Spectate); a change of the switch toasts "The host turned off spectator talk — you can still listen" / "Spectators can talk again"; role `none` stops any spectator voice and the pill reads "Voice is full (8 people)"; role `player` force-mutes watchers (pure spectators of the table by username: `watching` minus seat owners) while `spectatorsCanTalk` is off, and a player with `canChange` gets the "Spectators can talk" switch in the voice overlay (it waits for the echo, 5 s fallback). The mic button listen-only is a headphones button with `aria-disabled` only (it stays focusable and clickable): "Tap to talk" asks for the mic, "Listening only" says why and opens the overlay; M does the same (without the overlay). The overlay marks watchers "(watching)" and, while the switch is off, "listening only"; per-person volume and mute stay for everyone. A watcher speaking lights the spectator badge (`SpectatorBadge.setSpeaking`) and its row in the list, not a seat; a spectator viewer's seat 1 is the 'bottom' slot (`speakingSlotFor({spectator})`, it used to light nothing). The spectating pill adds "(listening only)". ## Voice TURN

- Voice TURN (owner, 2026-11-11: Cloudflare Realtime TURN, the PCM relay dropped): `getVoiceIceServers {requestId?}` (Joi, wrapper limit 20/min) → `voiceIceServers {iceServers, turn, expiresInSec, requestId?}` to the socket (`voiceHandlers.getVoiceIceServers`, `server/voice/turnCredentials.js`). Only a signed-in socket in a voice room (a lobby, a game, or an admitted voice spectator: `gameVoice.voiceRoomOf`) gets TURN (no new exposure: a lone lobby creator always got it); everyone else and every failure get the old Google STUN pair (`turn:false, expiresInSec:null`). Minting: `POST {base}/v1/turn/keys/{CLOUDFLARE_TURN_KEY_ID}/credentials/generate-ice-servers`, `Authorization: Bearer {CLOUDFLARE_TURN_API_TOKEN}`, `{ttl: 14400}` (4 h), 2.5 s timeout (AbortController), port-53 URLs dropped, body sanitized; cached in memory per username while ≥ 1 h is left, single flight per user, 60 s backoff after a failure, at most 120 mints per minute per process. Env unset = STUN only (voice as before). `CLOUDFLARE_TURN_API_BASE` points at a fake Cloudflare outside production only (ignored with a warning when NODE_ENV=production). Never log the token, the key id or a credential (failures log only the HTTP status or timeout/network). Web (`client/src/voice/VoiceChatManager.js`): `initialize` asks in parallel with the mic prompt and waits ≤ 4 s (else STUN); a TURN answer is reused per username for the tab and refreshed 30 min before expiry (`setConfiguration` on open connections), a STUN-only answer (the server's on any failure/backoff/unset env, or the 4 s fallback) is never kept, so each voice start and each restart ask again. A failed connection (`failed`, or not connected within 20 s: with no candidate pair Chromium never reports failed) gets one restart (the peer with the lower socket id refreshes the ICE servers and offers again on a new connection; the other refreshes too and waits 15 s for it), then the peer shows "voice unavailable" in the voice overlay (`isUnavailable`, `.voice-row__unavailable`); a later offer from it retries. No PCM relay any more (no ScriptProcessor, no `voiceRelayAudio` listener or emit); the server's handler, rate-limit key, Joi schema, both schema entries and the web constants went a day after the deploy (`contract/V1_REMOVALS.md` #20, done 2026-11-12): a `voiceRelayAudio` packet reaches no handler. iOS 1.1.0 is still STUN only; iOS 1.2.0 asks the same way (`Voice/IceServerStore.swift`: parallel with the mic prompt, 4 s, TURN reused per username and refreshed 30 min before expiry, one restart then "voice unavailable", 20 s connect timeout; V1_REMOVALS "iOS TURN"). Tests: `server/socket/__tests__/voiceIceServers.test.js`, `client/src/voice/VoiceChatManager.test.js`

## Web voice keys

- Web voice keys (`client/src/voice/voiceHotkeys.js`, installed by main.js; 2026-11-15): while voice is on, hold backquote (`` ` ``, `code === 'Backquote'`) for the voice overlay (`VoiceChatUI.showVoiceOverlay`, a kit modal), release to close; window blur closes it too (a key held into alt-tab never sends its keyup). M toggles mute. Both are ignored while focus is in an input, textarea, select or contenteditable and with ctrl / meta / alt held; an auto-repeat keydown never opens the overlay. The backquote is `preventDefault`ed only when it opens or holds the overlay, so a ` typed in chat still types. Tab is never touched: it used to be the overlay key and its `preventDefault` stopped keyboard focus moving for everyone with voice on. Tests: `client/src/voice/voiceHotkeysWiring.test.js` (main.js installs them and has no Tab handler, a source scan) and `client/src/voice/voiceHotkeys.test.js` (the hotkeys, and with the real overlay: the modal takes focus, keyup still closes it, focus comes back)

## iOS sounds and voice

- iOS per-player volume (iOS 1.2.2 build 10; web `VoiceChatUI` has the same 0-200% slider): `VoicePanelSheet` shows a slider under each remote player (`voice.volume.<username>`, VoiceOver "<name> volume", value "150%"; none for "You"). `VoiceChatManager.setPeerVolume(socketId, 0...2)` (`VoiceVolume.clamp`, 5% steps) stores it on `PeerInfo.volume` and by username (`savedVolumes`, in memory: a player back on a new socket or in the next game keeps theirs, which goes beyond the web, whose volumes are per socket and cleared on teardown; `forgetVolumes` clears them at sign-out) and sets the remote `RTCAudioTrack.source.volume` (WebRTC range 0...10, 1 = unity, so 2 boosts; the web caps the element at 1 and so cannot boost). Mute stays `isEnabled`, independent of the level. `setRemoteTrack` applies the stored mute and volume to a new track (first connect or a restart; before, a restart's track came up unmuted while the row still showed muted). Fixture `-uiVoicePanel YES`; tests `LobbyParityTests` (clamp, per-player store), `LobbyParityUITests.testEachPlayerHasAVolumeSlider`. Not yet heard on a device
- iOS table sounds and the audio session (2026-11-15; ships with the next iOS build, after 1.2.1 build 9): `VoiceChatManager.configureAudioSession` sets playAndRecord / voiceChat (`.defaultToSpeaker`, `.allowBluetoothHFP`) before `isActive` goes true, synchronously on the main actor, and `shutdown` deactivates the session (`.notifyOthersOnDeactivation`) without resetting the category. `SoundPlayer` (main actor) never sets the session while `VoiceChatManager.shared.isActive`: a sound then plays through voice's session (the silent switch does not mute it; not yet heard on a device). With voice off, right before each sound, any category but `.ambient` (the launch default soloAmbient, which would stop the user's music, or the playAndRecord voice left behind) is set to `.ambient`, which respects the silent switch and mixes with other audio (if that
category change throws, the sound is skipped: in soloAmbient it would stop the
user's music); nothing is activated by hand (AVAudioPlayer does that) and nothing touches the session before the first sound, so a muted player never does. Voice starting after that overrides it as before; voice stopping leaves playAndRecord inactive until the next sound puts ambient back. `SoundSessionPolicy.action(voiceActive:category:)`; tests `SoundEffectsTests.testPolicy`, `testAmbientWithoutVoiceAndUntouchedDuringVoice`, `testAFailedCategoryChangeSkipsTheSound` (injected `SoundSession`).
