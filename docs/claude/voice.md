# Voice: signaling, TURN and web keys

Never auto-loaded: open it for `server/socket/voiceHandlers.js`, `server/voice/`, `client/src/voice/` (including the `voiceHotkeys.js` overlay / mute keys), `client/src/ui/components/VoiceChatUI.js` or the iOS `Voice/` code.

## Voice signaling

- Voice signaling (`server/socket/voiceHandlers.js`; roadmap 30's security part, 2026-11-11): voiceOffer / voiceAnswer / voiceIceCandidate are forwarded only when the target is a connected socket id (`io.sockets.sockets`; never a room such as 'mainRoom' or `game:<id>`, never the sender), both sockets are signed in and share a lobby (`playerLobbies`) or a game (`playerGames`: entrants, seat owners incl. a lazy owner's socket) — the peers voicePeerList/voicePeerJoined announce; pure spectators are refused (web runs voice in the lobby and at a seat, iOS 1.1.0 only when `holdsSeat`) — and neither user blocked the other (`socket.data.blockedUsers`, set by `rememberBlockList` at signIn / restoreSession / signUp / rejoinGame's session-token check and on every blockListUpdated success; a CLI merge is seen at the next sign-in; each side is checked against its own list; a signed-in socket with no list fails closed, refused both ways while `loadBlockList` reads it, with a warning). Per-socket limits checked in-handler (`rateLimiter.limits`: offer/answer 30, ICE 300 per 10 s), then the payload's Joi schema (`validators.schemas.voiceOffer` etc., V1_REMOVALS #18; the contract's `joiInHandler`: target id <= 64, SDP type + sdp <= 64 KB, candidate fields bounded, nulls and iOS 1.1.0's "" allowed); every refusal is dropped silently (debug log; no reply, never `serverError`, which would toast). An established P2P stream is not torn down by a later block. Tests: `server/socket/__tests__/voiceSignaling.test.js`

## Voice TURN

- Voice TURN (owner, 2026-11-11: Cloudflare Realtime TURN, the PCM relay dropped): `getVoiceIceServers {requestId?}` (Joi, wrapper limit 20/min) → `voiceIceServers {iceServers, turn, expiresInSec, requestId?}` to the socket (`voiceHandlers.getVoiceIceServers`, `server/voice/turnCredentials.js`). Only a signed-in socket in a lobby or game (`playerLobbies`/`playerGames`, the voice peers) gets TURN; everyone else and every failure get the old Google STUN pair (`turn:false, expiresInSec:null`). Minting: `POST {base}/v1/turn/keys/{CLOUDFLARE_TURN_KEY_ID}/credentials/generate-ice-servers`, `Authorization: Bearer {CLOUDFLARE_TURN_API_TOKEN}`, `{ttl: 14400}` (4 h), 2.5 s timeout (AbortController), port-53 URLs dropped, body sanitized; cached in memory per username while ≥ 1 h is left, single flight per user, 60 s backoff after a failure, at most 120 mints per minute per process. Env unset = STUN only (voice as before). `CLOUDFLARE_TURN_API_BASE` points at a fake Cloudflare outside production only (ignored with a warning when NODE_ENV=production). Never log the token, the key id or a credential (failures log only the HTTP status or timeout/network). Web (`client/src/voice/VoiceChatManager.js`): `initialize` asks in parallel with the mic prompt and waits ≤ 4 s (else STUN); a TURN answer is reused per username for the tab and refreshed 30 min before expiry (`setConfiguration` on open connections), a STUN-only answer (the server's on any failure/backoff/unset env, or the 4 s fallback) is never kept, so each voice start and each restart ask again. A failed connection (`failed`, or not connected within 20 s: with no candidate pair Chromium never reports failed) gets one restart (the peer with the lower socket id refreshes the ICE servers and offers again on a new connection; the other refreshes too and waits 15 s for it), then the peer shows "voice unavailable" in the voice overlay (`isUnavailable`, `.voice-row__unavailable`); a later offer from it retries. No PCM relay any more (no ScriptProcessor, no `voiceRelayAudio` listener or emit); the server's handler, rate-limit key, Joi schema, both schema entries and the web constants went a day after the deploy (`contract/V1_REMOVALS.md` #20, done 2026-11-12): a `voiceRelayAudio` packet reaches no handler. iOS 1.1.0 is still STUN only; iOS 1.2.0 asks the same way (`Voice/IceServerStore.swift`: parallel with the mic prompt, 4 s, TURN reused per username and refreshed 30 min before expiry, one restart then "voice unavailable", 20 s connect timeout; V1_REMOVALS "iOS TURN"). Tests: `server/socket/__tests__/voiceIceServers.test.js`, `client/src/voice/VoiceChatManager.test.js`

## Web voice keys

- Web voice keys (`client/src/voice/voiceHotkeys.js`, installed by main.js; 2026-11-15): while voice is on, hold backquote (`` ` ``, `code === 'Backquote'`) for the voice overlay (`VoiceChatUI.showVoiceOverlay`, a kit modal), release to close; window blur closes it too (a key held into alt-tab never sends its keyup). M toggles mute. Both are ignored while focus is in an input, textarea, select or contenteditable and with ctrl / meta / alt held; an auto-repeat keydown never opens the overlay. The backquote is `preventDefault`ed only when it opens or holds the overlay, so a ` typed in chat still types. Tab is never touched: it used to be the overlay key and its `preventDefault` stopped keyboard focus moving for everyone with voice on. Tests: `client/src/voice/voiceHotkeysWiring.test.js` (main.js installs them and has no Tab handler, a source scan) and `client/src/voice/voiceHotkeys.test.js` (the hotkeys, and with the real overlay: the modal takes focus, keyup still closes it, focus comes back)

## iOS sounds and voice

- iOS table sounds and the audio session (2026-11-15; ships with the next iOS build, after 1.2.1 build 9): `VoiceChatManager.configureAudioSession` sets playAndRecord / voiceChat (`.defaultToSpeaker`, `.allowBluetoothHFP`) before `isActive` goes true, synchronously on the main actor, and `shutdown` deactivates the session (`.notifyOthersOnDeactivation`) without resetting the category. `SoundPlayer` (main actor) never sets the session while `VoiceChatManager.shared.isActive`: a sound then plays through voice's session (the silent switch does not mute it; not yet heard on a device). With voice off, right before each sound, any category but `.ambient` (the launch default soloAmbient, which would stop the user's music, or the playAndRecord voice left behind) is set to `.ambient`, which respects the silent switch and mixes with other audio; nothing is activated by hand (AVAudioPlayer does that) and nothing touches the session before the first sound, so a muted player never does. Voice starting after that overrides it as before; voice stopping leaves playAndRecord inactive until the next sound puts ambient back. `SoundSessionPolicy.action(voiceActive:category:)`; tests `SoundEffectsTests.testPolicy`, `testAmbientWithoutVoiceAndUntouchedDuringVoice` (injected `SoundSession`).
