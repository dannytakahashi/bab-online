# Web client: session, delivery, screens and phone gate

Never auto-loaded (it lives outside `client/`, which the server serves as static files: never put a doc there). Open it for any `client/` work outside the table; the table is `docs/claude/web-table.md`.

## Architecture

**Client:**
- `GameState` singleton replaces global variables
- `SocketManager` tracks listeners for cleanup (prevents memory leaks); after a background > 5 s it pings (requestSnapshot) and forces a reconnect only when the ping goes unanswered
- `ClientSession` (`client/src/state/ClientSession.js`) is the one owner of the screen (FSM BOOT/SIGN_IN/MAIN_ROOM/LOBBY/TOURNAMENT_LOBBY/TABLE(role)/GAME_END, explicit transition table; illegal → logs and fails closed, throws under Vitest; UIManager.showScreen goes through it), the table role, every gameId copy and the reconnect order: every connect restores the session first, then one rejoinGame per socket / re-spectate / re-enter the screen. The table is entered only via `enterTable(role, gameId)` and left only via `exitTable(reason)` (main.js `teardownTableUI` is its teardown; tournament players route back with returnToTournament). A restore records the server's `activeTournamentId` before any rejoin, so a failed rejoin returns to the tournament; a tab that only watches a tournament keeps `tournamentSpectate` in sessionStorage (a reload re-spectates, never `joinTournament`; its lobby shows no player controls; leaving a table it watched goes back to watching: `spectateTournament` from a socket the server does not know as the tournament's spectator, else `returnToTournament`). Deferred table rebuilds stop on a newer `tableGeneration` (each rejoinSuccess bumps it) or when the screen is no longer TABLE. GameState splits session identity (username, tournamentId — survive `reset()`; `resetSession()` clears them) from per-game state. Page-level tests: `client/src/sessionFlows.test.js`, `client/src/reload/*.test.js` (harness `client/src/testing/fakePage.js`)
- Manager pattern: specialized managers (CardManager, TrickManager, etc.)
- Client-side validation mirrors server for immediate UI feedback

## Web stay signed in

- Web "stay signed in" (`client/src/utils/sessionPersistence.js`): the tab's session is in `sessionStorage` (so 4-tab local testing still works) and the latest sign-in is mirrored to `localStorage`, which a fresh tab adopts on load. Profile page has a Sign Out button (shared family computers); it is client-only (no token revoked), so a tab parked behind the "open in another tab" notice signs itself out when the device's saved session is gone (the storage event, 'otherClosed', Use here: `isDeviceSignedOut`, `client/src/reload/supersededTabSignOut.test.js`); a parked tab whose socket reconnected (a deploy) is anonymous to the server, so its notice says only that the other tab may still be open. iOS keeps its token in the Keychain
- (Server side of the parked tab: `docs/claude/server-accounts.md`, Sessions and socket identity.)

## Web delivery

- Web delivery (`server/staticAssets.js`, `client/vite.config.js`): `/` and `/index.html` are the built `client/dist/index.html`, `Cache-Control: no-cache` (503 when not built); `/dist/assets/*` are content-hashed (`boot-[hash].js` the entry (src/entry.js, the phone gate), `main-[hash].js` the app chunk it imports (src/main.js), a `vendor-[hash].js` chunk for Phaser + socket.io-client that only changes with a library version, css) and immutable for a year; the pre-hashing entry `/dist/main.js` (its shim) and `client/socket-init.js` are gone (2026-11-11): the pages that loaded them were cached for at most a day before #201 (2026-11-09), an open old tab never fetches them again, and a reloaded one gets the current page, so they are plain 404s (no reload stub). The root static serves `client/` itself (1 day), so never leave a non-public file there. CSP (`server/middleware/csp.js`, every response; the page's meta CSP in client/index.html is enforced too, so a source must be in both: `server/__tests__/csp.test.js` keeps them in step): `script-src 'self'` only (no inline script, no CDN, no `'unsafe-eval'`: Phaser 3.55's one page-path eval, webpack's `new Function("return this")`, is rewritten to `globalThis` at build time by `vite.config.js` `phaserNoEval`, which fails the build if the pattern moves), `style-src 'self' 'unsafe-inline'` (style attributes; the /privacy-/support-/terms inline `<style>`), `font-src 'self'` (system font, no Google Fonts); connect-src keeps the production hosts. Chrome refuses eval silently (no console line): check with a `securitypolicyviolation` listener registered before the boot entry. gzip/brotli via `server/middleware/compression.js` (Express only: engine.io answers `/socket.io/` first; images are never encoded). Production builds drop `console.log`/`console.debug`. The web connection banner (`ui/components/ConnectionBanner.js`) follows `SocketManager.onStateChange`; after any reconnect outside a game the page restores its session (`restoreSessionAfterReconnect` in main.js), since the server no longer knows the new socket. Server restart (V1_REMOVALS #17 kept, owner 2026-11-11): every deploy's gracefulShutdown sends `serverShutdown` and closes every socket ~1 s later (a transport close: Socket.IO reconnects); web (authHandlers -> main.js `onServerShutdown`) shows the banner's calm restart text (`noteServerRestart`, same slot and polite live region, `.is-restart`) until connected, and records what the tab was in (`state/restartNotice.js`: seat / spectator / lobby / tournament / tournament spectator; nothing for the main room, a casual GAME_END or a parked tab; sessionStorage `bab.serverRestart` with a timestamp, 2 min) so the first restore path that finds it gone (rejoinFailed, the re-spectate / lobby / tournament re-entry refusal, tournamentLeft) shows ONE info toast ("Your game ended because the server restarted for an update. It won't count toward your stats." — true: only the end path's recordGameStats writes stats / gameRecords), later paths stay quiet, and a place that survived (rejoinSuccess, lobbyCreated, tournamentJoined, the spectator state) clears it (`client/src/reload/serverRestart*.test.js`)

## Full-window screens

- Full-window screens (owner decision 2026-11-11): the main room, game lobby and tournament lobby are `.screen--full` (`client/styles/screens.css`): fixed to the whole window, one grid with the header (title, nav, online count) across the top, the content on the left (`.screen-main`: lobby list + create buttons / seats + Ready, Add Bot, Leave / scoreboard, the round's tables beside the players (`.tournament-roster`), controls) and the chat full height on the right (`.screen-chat`, as iOS PR 198), DOM and focus order the same; content capped at `--screen-cap` 1400 px and centred, chat `--screen-chat-w` clamp(360px, 30vw, 480px); compact below 1100 px (chat clamp(280px, 32vw, 340px)), stacked below 760 px; the page never scrolls (lists, scoreboard and chat logs scroll inside, the tournament's standings and roster shrink to `--screen-min-scroller`) down to 1024x668; a window too short for the content column (stacked at ~700x600) scrolls `.screen--full > .screen-main` itself (padding / negative margin `--space-1` keep focus rings inside the clip). Lobby voice buttons live in the lobby header's `#lobbyVoiceSlot` (`GameLobby.js` `LOBBY_VOICE_SLOT_ID`; `VoiceChatUI.js` `placeVoiceButton`), not the window corner (the chat's Send is there and the lobby is a window-sized z-panel layer); a lobby re-render carries them into the new header and `removeGameLobby` hands them back to the page so voice carries into the table's HUD slot. Chat logs follow the newest message only while the reader is at the end (`common.js` `appendChatLine` / `followChatOnResize`, 24 px slack). Tests: `client/src/ui/screens/fullWindow.test.js` (column model from the stylesheet at the named viewports, DOM/focus order, computed style, chat stickiness, modals over the room, fault injection)

## Phone gate

- Phone gate (web item 19, owner decision 2026-11-11; `client/src/boot/`): phones get the native app instead of the web client (no phone layout is planned). `src/entry.js` is the page's entry (`boot-[hash].js`, ~3 KB brotli, no static imports: `vite.config.js` fails the build otherwise); it decides (`deviceGate.decideBoot`), then `import('./main.js')` (main.js `startApp` runs once, on load or from boot when the chunk lands after load) or shows the gate (`gateScreen.showGate`) and never fetches the app chunk, so a gated phone opens no socket and is never online; saved sessions are never read or cleared. Phone = `(pointer: coarse)` AND `(hover: none)` AND `Math.min(screen.width, screen.height) < 600` CSS px (`PHONE_MAX_SHORT_SIDE`: iPhones <= 440, iPad mini 744, 7-inch Android tablets 600; the same 600 the iOS app uses for its rotation rule; the screen, not the window, so rotation, split view and narrow desktop windows never change it); a desktop-OS UA (`isDesktopOSUA`: CrOS, Windows NT, X11 without Android) is never a phone, so a Chromebook/Windows tablet in tablet mode with an enlarged display size is not gated (an Android phone asking for the desktop site sends X11 and goes ungated: accepted fail-open; such tablets get no app-chunk preload, the import fetches it); a missing or throwing API fails open (no gate). While a phone's gate is up, boot re-checks on `resize` / the `NOT_PHONE_MEDIA` change: a foldable unfolded to a tablet-size screen lifts the gate and boots WITHOUT remembering Continue (a forced `?gate=1` never lifts). A failed app-chunk import from the gate (a deploy removed the page's `main-[hash].js`, 404) reloads the page once (Continue is already remembered; storage that throws: `location.replace` with `?web=1`); offline (`navigator.onLine === false`) or a reload that throws keeps the gate's "check your connection" message. Variants: iPhone/iPod UA (or a touch "Macintosh" UA, an iPhone asking for the desktop site) gets "Get the iPhone app", a plain https link to `APP_STORE_URL` (`https://apps.apple.com/app/id6759510890`, storefront-neutral; owner's link `https://apps.apple.com/us/app/bab-online/id6759510890`); Android and other phones get "made for bigger screens. Play on a computer or tablet." with no store button. Both have "Continue in browser anyway", remembered in localStorage `bab.phoneGate.continue` (storage that throws: this page only), after which the app boots exactly as before (the phone-size site is unoptimized). Escape hatches: `?web=1` = Continue (and remembers it), `?gate=1` shows the gate on any device ignoring the remembered choice (`?gate=ios` / `?gate=other` pick the variant); to un-remember, clear the key. iPads, tablets, desktops, touch laptops (hover) are never gated. The build preloads the app chunk with `<link rel=modulepreload media=NOT_PHONE_MEDIA>` (honored by Chromium and iOS Safari; no modulepreload polyfill, which would ignore media), so a desktop starts the download with the entry and a phone never fetches it. index.html carries the Smart App Banner (`apple-itunes-app` app-id=6759510890; iPad web stays allowed). While the gate shows it adds `viewport-fit=cover` (restored on close). Styles `client/styles/gate.css` (tokens, Dynamic Type via `-apple-system-body`, a side-by-side landscape layout, scrolls when it does not fit). Tests: `src/boot/deviceGate.test.js` (device matrix, escape hatches, storage), `src/boot/boot.test.js` (no app import when gated, Continue, DOM, focus order)

## Stats scope (Leaderboard, Records, Profile)

- Stats scope (owner 2026-11-13; server side `docs/claude/server-infra.md` Stats scopes): one choice per device, `client/src/state/statsScope.js` (`getStatsScope`/`setStatsScope` in localStorage key `bab.statsScope`, every access in try/catch; blocked storage keeps the choice for this page only; anything invalid = `human`), shared by the Leaderboard, Records, own Profile and other players' profiles. `client/src/ui/components/StatsScopeControl.js` is the "Human games | Bot games | All games" segmented control at the top of each (a WAI-ARIA radiogroup: one tab stop, arrows move and select with wrap, Home/End; `aria-controls` the region it updates; styles `.scope-control*`, `.scope-region[aria-busy]`, `.scope-note` in screens.css). Every stats request carries `{scope}` (`scopePayload`: MainRoom nav, PlayerSearchPage rows, GameScene's own avatar, OpponentManager plates); a switch saves the choice, marks the region `aria-busy` (dimmed) and re-asks after 200 ms (`createScopeRequester`: arrowing through the options sends one request; the server's 10 per 10 s budget is shared by the scopes). main.js drops a reply whose echoed `scope` is not the current choice (`isStaleScopeReply`; a reply without one, e.g. a failure, is never stale) and updates an open page IN PLACE (`updateLeaderboardPage` keeps the sort, `updateRecordsPage`, `updateProfileStats` / `updatePlayerProfileStats` replace only the stats grid), so the modal never reopens and focus stays on the control; a failure clears the wait (`leaderboardRequestFailed` etc.) and shows the usual toast. An empty Bot games view says "No bot games recorded yet. Games with bots count toward stats from now on." (`BOT_STATS_EMPTY_NOTE`). Bot personas in records arrive as plain strings ('🤖 Mary'). Tests: `statsScope.test.js`, `StatsScopeControl.test.js`, `statsScopePages.test.js`
