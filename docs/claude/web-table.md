# Web table: state, rendering, layout and design system

Never auto-loaded: open it for `client/src/state/`, `client/src/phaser/`, `client/src/table/`, `client/src/audio/`, the HUD, `client/styles/` or `client/tokens/`. Snapshot v2 and seq rules: `contract/CLAUDE.md`.

## Web table

- Web table (item 16): `client/src/state/GameState.js` is the ONE writer of table state: `handlers/gameHandlers.js` applies each event (`applyDeal/applyBid/applyCardPlayed/applyTrickComplete`...; trick counts and trumpBroken live there, never in the scene; playerLazyMode/playerActiveMode/playerResigned write the seat's name and picture with `applySeatDisplay`, so a re-render keeps the bot, and `GameScene.showSeatDisplay` redraws that seat (my own box: name, tooltip, alt, click target; or the avatar) and the score header from it at once: `client/src/table/seatDisplay.test.js`) the draw for deal so far is `GameState.draw` (startDraw / playerDrew / youDrew, or a DRAWING snapshot's `draw`; `renderModel().draw` in DRAWING / DRAW_RESOLVING), so a render mid-draw (a rejoin, or a spectator: main.js `onSpectatorJoined` also enters the table on a DRAWING snapshot, as iOS shows a spectator the draws) draws the draw, not an empty table (`DrawManager.renderDraw`); and every snapshot goes through `state/tableSync.applyTableSnapshot` (parse v2, else `state/legacySnapshot.js` from the v1 fields → `GameState.applySnapshot` → `MyAction.reconcile` → render → `SeqGate.onSnapshot`). `state/SeqGate.js` (R1-R5) wraps every SocketManager listener (`setGate` before the handler modules register): a gap buffers and sends `requestSnapshot {requestId:'gap-N', log:false, customPics:false}`, the reply replays what is above S; baselines reset at startDraw / another gameId's gameStart / gameEnd / abortGame. `GameScene.render(model)` (model = `GameState.renderModel()`, snapshot shaped) clears every manager and draws the table idempotently (opponent backs from `seatCards`, trump face up, stacks from the snapshot's `trickHistory` or the hand's own history, else face-down placeholders: `table/reloadWonTricks.test.js`, `reloadFaces.test.js`); main.js `renderTable` adds the log (replaced with a DocumentFragment from `snapshot.log` unless `partial` has 'log'), header, indicators, pill. `phaser/TableDirector.js` owns every delayedCall/tween (managers use `sceneDelay`/`sceneTween`), keyed {gameId, handNo, deal, trickNo} (scope 'deal'/'trick' work skips a later key; `reset()` cancels all, render calls it), buffers scene work until GameScene has its managers (`run`, by tableGeneration; a late flush ends with one render), gates the first deal on the createUI fade (`uiReady`) and later deals on the trick whisk (`afterTransition`; a play during the wait `settleDeal`s), and fast-forwards (cancel + render) when a hidden tab comes back with anything changed or in flight. No window flags/events (`_transitionOverlay`, `_readyForGameUI`, `_tricksAnimating`, trumpFlipComplete/gameUIReady/tricksCleared are gone; `ui/transitionOverlay.js` keeps the overlay handle). `state/MyAction.js`: one pending bid/play (idle → pending → confirmed by my own cardPlayed/bidReceived, or rolled back by actionRejected's snapshot); a click never edits GameState (renderModel hides the pending card); after 5 s without an answer `requestSnapshot 'ack-N'` and reconcile (card gone from the hand = accepted; a 'gap-'/'ping-' reply, whose request may predate the action, that still shows my turn keeps it pending), a second silence forces a reconnect, never a blind rollback; a click on a disconnected socket is ignored. Tests: `client/src/table/*.test.js` run the real GameScene/managers on `testing/fakePhaser.js` and replay the recorded games in `iOSClient/BABOnlineTests/Fixtures/events` (read only) and `contract/fixtures/v2` (`testing/replay.js`: counts vs every checkpoint snapshot, rejoin on a live scene vs a fresh render)

## Web table layout

- Web table layout (item 17): `client/src/phaser/layout/computeTableLayout.js` is the ONE source of table geometry, a pure function of the canvas size (`{w, h, dpr, isSpectator, logW}`): one size scale `s` (<= 1) for every sprite and DOM size, SOLVED by searching s (and the trick history's own 1 / 0.85 / 0.7 step, a roomy then a compact hand box) for the first layout with no rect intersections and nothing off the canvas, checked by the same `findIntersections` / `findOutside` the tests use; positions are today's fractions of the canvas where they fit (1920x1080 keeps the old table). It returns per seat (self, partner, opp1, opp2; a spectator's self is the bottom seat) the avatar, plate, card fan, bubble and dealer anchors, the trick slots and play zone, both history blocks (13 slots each), the hand box, trump, the felt (today's 0.3125 x 0.42 of the window where the side seats can move out for it, tried after s is solved) and the bid sheet inside it (it may cover only the empty trick), each seat's bubble direction and max width (at its largest, 3 lines, it never covers the trump, hand, trick slots, histories or another bubble: `BUBBLE_KEEPS` in the same check), status pill, voice slot, spectator badge (`spectators`: the player's bottom-right corner, else beside the voice row / up the right edge; a spectator's beside the corner voice slot; in BUBBLE_KEEPS; where a phone-size bubble needs the corner the badge gives way), the draw for deal (`placeDraw`, iOS DrawPhaseView's column: title and rule, four slots in draw order each an avatar / name / card (at least the hand card, grown into the spare height by up to `DRAW_GROW.max` (avatar and name by half as much) and drawn from its own 1:1 frame, `phaser/cards/drawSlotFaces.js` texture 'drawSlots', never an upscaled atlas frame; its centre on a device pixel; the name at least s3 above it; all four cards on one row), the deck and its prompt, centred; type and spacing are the tokens at s and only the gaps around the slot row give way, so the draw never decides s; the HUD (`ui/drawHud.js`) keeps a slot's dashed placeholder until its card turns up (`landDrawSlot`), shrinks a long name to 0.6 before the ellipsis (`fitName`), and says each draw and the teams on status lines (focus goes there when the focused Draw a card button goes); `drawRects`), the teams panel and effects. Managers read it through `layoutOf(scene)` / `GameScene.getLayout()`; no manager keeps a design size. The DOM lives in the HUD (`client/src/ui/tableHud.js`, `#table-hud` inside `#game-container`): one `.hud-seat` per seat at its avatar centre, the avatar, frog and chat/bid bubble are its children; status pill, bid sheet, voice buttons and the spectator badge (`.hud-spectators`, `hudSpectatorSlot`) are HUD slots; the draw for deal's words and players are `ui/drawHud.js` (`.hud-draw`: title, rule, slots with avatar, name and a dashed placeholder, the prompt and a keyboard "Draw a card" button; `.hud-teams`: a scrim and the teams panel, each player's avatar from the seats' pictures), its cards stay on the canvas (`DrawManager`); `applyHudLayout` sets every position as CSS variables; `clearHud` is the teardown. The log and canvas share one grid (`#table-shell`, `--log-w` breakpoints in styles.css mirrored by `LOG_BREAKPOINTS`; `setTableChrome(on)` toggles the column, a ResizeObserver keeps Phaser's canvas on its column). `GameScene.relayout()` runs on every resize: with work in flight (deal, fly-in, collect, whisk) the director fast-forwards (`settleForRelayout` -> render at the new size), else every manager snaps to the new layout (relayout then render draws the same table). A Phaser shape resized in place goes through `phaser/shapes.js` `resizeShape` (3.55's Rectangle.setSize keeps the old display origin). Tests: `computeTableLayout.test.js` (6 named viewports x 2 roles, a 2000+ size sweep), `client/src/table/relayout.test.js` (real scene: draw hit testing, mid-deal / mid-trick / hover / relayout-equals-render), `client/src/table/drawPhase.test.js` and `drawSpectator.test.js` (the draw's HUD, my clicked card to my slot, auto-draw / keyboard / spectator / teams / a render mid-draw, a spectator who joins mid-draw (events-humans-s13) through to the game end)

## Keyboard card play (web a11y)

- Keyboard hand (review later #7, 2026-11; web only, no wire change, iOS untouched): the canvas hand is mirrored into the HUD by `client/src/ui/handA11y.js`, driven by `CardManager._syncA11y()` on every hand or legality change (displayHand, updateCardLegality, setInteractive, the tint setters, extract / remove / play, clearHand, repositionHand, so every relayout). `.hud-hand` is a `role="toolbar"` "Your hand": one `<button>` per card in hand order, `aria-label` the card name (`getCardDisplayName`, "Queen of Hearts", "High Joker"), `aria-disabled="true"` exactly when the canvas dims it (the sprite's `isLegal`, i.e. the same client legality, `rules/legality.js`, as the pointer; not your turn, bidding, a pending play, a lazy seat and a trick still collecting all dim). Each button sits over its card's VISIBLE strip (the layout's `handPositions` and `hand.card`, as `--x/--y/--w/--h`; the rightmost cards sit on top, so the strip's centre is that card on the canvas, which is what a touch screen reader taps: `objectsAt` in the test), is invisible and `pointer-events: none` (the canvas keeps clicks and hover), and draws a ring round the whole card on `:focus-visible` (raised with a playable card, which lifts as on hover: `CardManager._raiseCard` / `_lowerCard`, shared with pointerover/out; a hover-out never drops the focused card, and `repositionHand` (every relayout) raises it again after its snap). One tab stop (roving tabindex, on the focused card, else the first playable); Left / Up and Right / Down move, Home / End; Enter / Space are the button's own click. A click on a playable card calls `CardManager._activate(sprite)`, the very call pointerdown makes, so it is the pointer's path (`GameScene.handleDisplayHand`'s handler: connected check, `MyAction.submitPlay`, the fly-in); on a dimmed card it plays nothing and the announcer says why (`GameScene.illegalReason`: "Not your turn.", "Bid first.", "Must follow suit.", ...). No other key is taken: the voice keys (hold backquote, M; `voice/voiceHotkeys.js`) work with a card focused. Focus: my play turn OPENING (`updateCardLegality` canPlay false -> true, so a render of the same turn does not) moves focus to the first playable card only when focus is nowhere (the body) after a navigation key (Tab, arrows, Home / End, Enter, Space; a pointer user's voice keys or a stray letter do not count, so their focus never moves) or on the table's own controls (`.hud-hand`, the announcer, `#bidContainer`, `.hud-draw`, `.hud-teams`); never from the chat input, any input / textarea / select / contenteditable, a modal, the voice overlay or any other control. The focused card going (played) hands focus to the card now in its place, the last one to the announcer (never the body), where it waits through the next deal for my turn (the new hand never pulls it in, even holding that card); a render (`clearAll({ redraw: true })`, then the same hand in the same task) puts it back on the same card, and `displayHand` syncs once after its own clear so a redraw never moves it. `.hud-announcer` is a visually hidden `role="log"` `aria-live="polite"`: each message a new line (the last `ANNOUNCE_KEEP` kept; the same words within 1 s dropped): the deal ("New hand of 8 cards. Trump is the Seven of Spades.", from `displayTrumpCard`'s face-down path only, never a render), my turn ("Your turn to bid." / "Your turn to lead." / "Your turn. On the trick: Ann, King of Hearts; Bob, 2 of Hearts."), each card played ("Ann played the ...", "You played the ..."), each trick ("Ann won the trick. Tricks: your team 3, opponents 2."; a spectator gets no tally) and the hand ("Hand over. Score: your team 120, opponents 80."). The bid sheet and the draw's "Draw a card" button are unchanged. It is layout-independent (every `computeTableLayout` size; a phone that chose "Continue in browser" and a Duo-size fold get the same toolbar), a spectator has no hand (no toolbar; the announcer still says plays, tricks and the trump). Styles: `client/styles/table.css` (`.hud-hand`, `.hud-announcer`). Tests: `client/src/ui/handA11y.test.js` (toolbar, keys, dimmed cards, focus hand-off and restore, the last card not pulling focus into the next deal, when my turn may take focus incl. after the voice keys, the log) and `client/src/table/keyboardHand.test.js` (events-bots-s12 seat 1 on the real scene: buttons vs sprites and their legality, the canvas card under each strip at five viewport sizes with the focused card raised after each, arrows, a dimmed card sends nothing, Enter = the pointer's handler with the same arguments and the same `playCard` emit, focus to the neighbour, render keeps focus, chat input keeps focus on my turn, focus nowhere after a key press goes to my first playable card, the announcer's lines)

## Web table sound

- Sound effects (owner 2026-11-15: tasteful; on by default, quiet, one easy mute per device; web first, iOS with its next build; the files are `npm run build:sounds`, `client/assets/sounds/*.m4a`, imported `?url` so the build hashes them, never inlined: vite `assetsInlineLimit`): `client/src/audio/SoundManager.js` is the player: its OWN AudioContext (voice chat keeps its own), created on the first pointerdown / keydown / touchend (`installUnlock` from startApp; a muted device creates none until it turns sound on, which is a click) and resumed by any later gesture (iOS suspends it in the background), the 11 files fetched (connect-src 'self'; no CSP change) and decoded once then (a file that failed is fetched again by a later gesture, `LOAD_RETRY_MS` 5 s apart, `LOAD_TRIES` 3 loads in all); off the table (main.js `syncTableScreen` -> `setActive`: only TABLE / GAME_END are active) the context is suspended, since a running one keeps the audio device awake, and back at a table it resumes (the page's earlier gesture allows it; where a browser still refuses, the next gesture at the table; not checked in a real browser); until it runs, and while muted, the volume is 0 or `document.hidden`, `play()` is a silent no-op (nothing is queued, so a tab coming back makes no burst); a master gain at `DEFAULT_VOLUME` 0.35; localStorage `bab.sound` `{muted, volume}` (every access in try/catch; blocked or junk storage = the defaults, the choice kept for the page; another tab's change follows via the storage event); mute sets the master gain to 0 at once; the same sound at most once per `THROTTLE_MS` 80 (the card-1/2/3 variants are one sound, `play('card')` never repeats the last variant); a failure is logged once per kind and never thrown. Web Audio on iPadOS Safari should follow the silent switch by default (not checked on a device; while voice holds the mic the session is play-and-record, which may not), and the page sets no `navigator.audioSession` type, which would fight voice. `client/src/audio/tableSounds.js` maps events to sounds, called by `handlers/gameHandlers.js` after GameState applied the event: playerDrew -> `draw` (owner 2026-11-16: the draw for deal had no sound) for a new draw order only (`GameState.applyPlayerDrew` returns whether it was new; mine and the bots'; not youDrew, not a snapshot's drawn cards), a card variant at `DRAW_GAIN` 0.8 under its own name (its own throttle in SoundManager), draws that arrive together `DRAW_SPACING_MS` 150 apart through a cancellable timer (a snapshot / `synced` and `reset` drop the waiting ones), gameStart -> `deal` when the cards go down (main.js showCards, `dealShown`: after the first hand's fade or the whisk), every cardPlayed -> `card` plus `overtrump` 90 ms later at 0.8 when `rules/overTrump.js` says so, updateTurn -> `turn` only on the edge into MY turn to bid or play (my own bid / play ends it; doneBidding's lead is cued by the updateTurn after it; never a spectator or a lazy seat), as a reminder only (owner 2026-11-15, "only if the player doesn't play for 5s"): `TURN_IDLE_MS` 5000 after the turn began (`_armTurnReminder`, a cancellable timer, not an AudioContext delay), it sounds only if the turn is still mine and open; my own bid / card, the turn moving on, a deal, a snapshot (`synced`) and gameEnd cancel it, and a new turn restarts it; a bid turn that comes before this deal's trump is face up (the server sends the next hand's gameStart and updateTurn with handComplete) counts from the flip, when the bid panel opens (`trumpShown` from main.js onFlipped), and is dropped when the turn moved on or a snapshot came first, trickComplete -> `trick-ours` by seat parity else `trick`, handComplete (before resetForNewHand) -> `made` when my team's tricks reach `bidTotalsFor(...).team` (a bore = the hand) else `set`, gameEnd -> `gameend`, `GAME_END_AFTER_HAND_S` 0.5 after the last hand's made / set (the server sends both in one tick). A spectator hears deal, cards, over-trump, the neutral `trick`, every hand end as `made` at `SPECTATOR_HAND_END_GAIN` 0.6 (no team, so no verdict: the score is in) and `gameend`, never a turn cue; a lazy watcher keeps its seat's team. Never on catch-up: `SeqGate.replaying` (events replayed after a gap snapshot or flushed after the timeout) silences every sound, and `state/tableSync.applyTableSnapshot` (rejoin, restore, spectate, resync, actionRejected) plays nothing and calls `synced()`, so the turn a snapshot restores is no edge and a deal waiting for its cards is dropped; teardown resets it.
