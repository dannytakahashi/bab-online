# Web table: state, rendering, layout and design system

Never auto-loaded: open it for `client/src/state/`, `client/src/phaser/`, `client/src/table/`, the HUD, `client/styles/` or `client/tokens/`. Snapshot v2 and seq rules: `contract/CLAUDE.md`.

## Web table

- Web table (item 16): `client/src/state/GameState.js` is the ONE writer of table state: `handlers/gameHandlers.js` applies each event (`applyDeal/applyBid/applyCardPlayed/applyTrickComplete`...; trick counts and trumpBroken live there, never in the scene; playerLazyMode/playerActiveMode/playerResigned write the seat's name and picture with `applySeatDisplay`, so a re-render keeps the bot, and `GameScene.showSeatDisplay` redraws that seat (my own box: name, tooltip, alt, click target; or the avatar) and the score header from it at once: `client/src/table/seatDisplay.test.js`) the draw for deal so far is `GameState.draw` (startDraw / playerDrew / youDrew, or a DRAWING snapshot's `draw`; `renderModel().draw` in DRAWING / DRAW_RESOLVING), so a render mid-draw (a rejoin, or a spectator: main.js `onSpectatorJoined` also enters the table on a DRAWING snapshot, as iOS shows a spectator the draws) draws the draw, not an empty table (`DrawManager.renderDraw`); and every snapshot goes through `state/tableSync.applyTableSnapshot` (parse v2, else `state/legacySnapshot.js` from the v1 fields → `GameState.applySnapshot` → `MyAction.reconcile` → render → `SeqGate.onSnapshot`). `state/SeqGate.js` (R1-R5) wraps every SocketManager listener (`setGate` before the handler modules register): a gap buffers and sends `requestSnapshot {requestId:'gap-N', log:false, customPics:false}`, the reply replays what is above S; baselines reset at startDraw / another gameId's gameStart / gameEnd / abortGame. `GameScene.render(model)` (model = `GameState.renderModel()`, snapshot shaped) clears every manager and draws the table idempotently (opponent backs from `seatCards`, trump face up, stacks from the snapshot's `trickHistory` or the hand's own history, else face-down placeholders: `table/reloadWonTricks.test.js`, `reloadFaces.test.js`); main.js `renderTable` adds the log (replaced with a DocumentFragment from `snapshot.log` unless `partial` has 'log'), header, indicators, pill. `phaser/TableDirector.js` owns every delayedCall/tween (managers use `sceneDelay`/`sceneTween`), keyed {gameId, handNo, deal, trickNo} (scope 'deal'/'trick' work skips a later key; `reset()` cancels all, render calls it), buffers scene work until GameScene has its managers (`run`, by tableGeneration; a late flush ends with one render), gates the first deal on the createUI fade (`uiReady`) and later deals on the trick whisk (`afterTransition`; a play during the wait `settleDeal`s), and fast-forwards (cancel + render) when a hidden tab comes back with anything changed or in flight. No window flags/events (`_transitionOverlay`, `_readyForGameUI`, `_tricksAnimating`, trumpFlipComplete/gameUIReady/tricksCleared are gone; `ui/transitionOverlay.js` keeps the overlay handle). `state/MyAction.js`: one pending bid/play (idle → pending → confirmed by my own cardPlayed/bidReceived, or rolled back by actionRejected's snapshot); a click never edits GameState (renderModel hides the pending card); after 5 s without an answer `requestSnapshot 'ack-N'` and reconcile (card gone from the hand = accepted; a 'gap-'/'ping-' reply, whose request may predate the action, that still shows my turn keeps it pending), a second silence forces a reconnect, never a blind rollback; a click on a disconnected socket is ignored. Tests: `client/src/table/*.test.js` run the real GameScene/managers on `testing/fakePhaser.js` and replay the recorded games in `iOSClient/BABOnlineTests/Fixtures/events` (read only) and `contract/fixtures/v2` (`testing/replay.js`: counts vs every checkpoint snapshot, rejoin on a live scene vs a fresh render)

## Web table layout

- Web table layout (item 17): `client/src/phaser/layout/computeTableLayout.js` is the ONE source of table geometry, a pure function of the canvas size (`{w, h, dpr, isSpectator, logW}`): one size scale `s` (<= 1) for every sprite and DOM size, SOLVED by searching s (and the trick history's own 1 / 0.85 / 0.7 step, a roomy then a compact hand box) for the first layout with no rect intersections and nothing off the canvas, checked by the same `findIntersections` / `findOutside` the tests use; positions are today's fractions of the canvas where they fit (1920x1080 keeps the old table). It returns per seat (self, partner, opp1, opp2; a spectator's self is the bottom seat) the avatar, plate, card fan, bubble and dealer anchors, the trick slots and play zone, both history blocks (13 slots each), the hand box, trump, the felt (today's 0.3125 x 0.42 of the window where the side seats can move out for it, tried after s is solved) and the bid sheet inside it (it may cover only the empty trick), each seat's bubble direction and max width (at its largest, 3 lines, it never covers the trump, hand, trick slots, histories or another bubble: `BUBBLE_KEEPS` in the same check), status pill, voice slot, spectator badge (`spectators`: the player's bottom-right corner, else beside the voice row / up the right edge; a spectator's beside the corner voice slot; in BUBBLE_KEEPS; where a phone-size bubble needs the corner the badge gives way), the draw for deal (`placeDraw`, iOS DrawPhaseView's column: title and rule, four slots in draw order each an avatar / name / card (at least the hand card, grown into the spare height by up to `DRAW_GROW.max` (avatar and name by half as much) and drawn from its own 1:1 frame, `phaser/cards/drawSlotFaces.js` texture 'drawSlots', never an upscaled atlas frame; its centre on a device pixel; the name at least s3 above it; all four cards on one row), the deck and its prompt, centred; type and spacing are the tokens at s and only the gaps around the slot row give way, so the draw never decides s; the HUD (`ui/drawHud.js`) keeps a slot's dashed placeholder until its card turns up (`landDrawSlot`), shrinks a long name to 0.6 before the ellipsis (`fitName`), and says each draw and the teams on status lines (focus goes there when the focused Draw a card button goes); `drawRects`), the teams panel and effects. Managers read it through `layoutOf(scene)` / `GameScene.getLayout()`; no manager keeps a design size. The DOM lives in the HUD (`client/src/ui/tableHud.js`, `#table-hud` inside `#game-container`): one `.hud-seat` per seat at its avatar centre, the avatar, frog and chat/bid bubble are its children; status pill, bid sheet, voice buttons and the spectator badge (`.hud-spectators`, `hudSpectatorSlot`) are HUD slots; the draw for deal's words and players are `ui/drawHud.js` (`.hud-draw`: title, rule, slots with avatar, name and a dashed placeholder, the prompt and a keyboard "Draw a card" button; `.hud-teams`: a scrim and the teams panel, each player's avatar from the seats' pictures), its cards stay on the canvas (`DrawManager`); `applyHudLayout` sets every position as CSS variables; `clearHud` is the teardown. The log and canvas share one grid (`#table-shell`, `--log-w` breakpoints in styles.css mirrored by `LOG_BREAKPOINTS`; `setTableChrome(on)` toggles the column, a ResizeObserver keeps Phaser's canvas on its column). `GameScene.relayout()` runs on every resize: with work in flight (deal, fly-in, collect, whisk) the director fast-forwards (`settleForRelayout` -> render at the new size), else every manager snaps to the new layout (relayout then render draws the same table). A Phaser shape resized in place goes through `phaser/shapes.js` `resizeShape` (3.55's Rectangle.setSize keeps the old display origin). Tests: `computeTableLayout.test.js` (6 named viewports x 2 roles, a 2000+ size sweep), `client/src/table/relayout.test.js` (real scene: draw hit testing, mid-deal / mid-trick / hover / relayout-equals-render), `client/src/table/drawPhase.test.js` and `drawSpectator.test.js` (the draw's HUD, my clicked card to my slot, auto-draw / keyboard / spectator / teams / a render mid-draw, a spectator who joins mid-draw (events-humans-s13) through to the game end)

## Web design system

- Web design system (item 18a): `client/tokens/tokens.json` is the ONE source of colors, type, spacing, radii, elevation, z-index and motion; `npm run tokens` (`scripts/build-tokens.js` over `client/tokens/generate.mjs`) writes `client/styles/tokens.css`, `client/src/ui/tokens.js` and the iOS app's `iOSClient/BABOnline/Generated/Theme.swift` (item 29; iOS views/nodes use the roles in `Extensions/Theme+Roles.swift`, never a color literal; README "iOS Client Architecture") (never hand-edit; `src/ui/tokens.test.js` fails when stale and checks every text-on-surface pair against WCAG AA). The kit is `client/styles/kit.css` + `client/src/ui/kit/` (Button: primary never red, IconButton 44 px target, Input, Panel, Chip, Avatar, Modal with focus trap / Escape where safe / focus restore, ONE Toast queue that Toast.js and main.js use; an error goes ahead of any other toast, a warning ahead of info/success, and one that outranks the toast on screen replaces it at once); the table reskin is `client/styles/table.css` (felt on `#game-container.at-table`, rail, glass seat plates with team rings, `ui/seatPlates.js` bid chips and trick pips: per player (owner, 2026-11-11), each ring the seat's OWN bid as slots and its own tricks won (GameState `tricksByPosition`, from applyTrickComplete or the snapshot's tricksByPosition, which wins over trickHistory winners), past its bid `is-over`, a 0 bid no slots; a bore seat (B-4B) the hand size as slots filled with the TEAM's tricks (both rings when both partners bore), its box outlined in the bore chip's red (`.hud-pips.is-bore`); the box is hit-tested (never `pointer-events: none`, a click bubbles to the seat) so its title (`2 of 3`, `Team 7 of 10 (bore)`) shows on hover; a seat whose count a v1 snapshot cannot give (null) shows its team's tricks out of the team total; `client/src/table/seatPips*.test.js` replay the recordings against the server's counts). The table's HUD files use no hex literal and no inline style (`src/ui/hudStyles.test.js`; geometry only as CSS variables). Motion: `ui/motion.js` (`motionMs`, live `prefers-reduced-motion`); only cosmetic durations use it, the pacing-sized fly-in/collect/teams fade do not; the only infinite animation is the opacity-only turn ring. Cards are drawn, not loaded: `phaser/cards/cardFaces.js` (the iOS CardTextureGenerator on 300 x 435, suits as paths; the back is iOS PR 239's, the app icon's four suits; web faces since 2026-11 differ from iOS: ONE jumbo index at the top left, `INDEX` (bold 100 rank, the "10" at full width, never condensed: a font whose "10" passes `maxInkW` shrinks every rank alike, `rankSize`), no bottom-right index, a 200-unit pip `PIP` under it; the jokers are the old pixel-art sprite redrawn (slate outline, light-blue border and panel, the dollar glyph) with HI (card red) / LO (card black) as the corner index; `cardFaces.test.js` keeps the index inside the tightest hand strip over the desktop size sweep) into one atlas (`cards/CardAtlas.js`, texture 'cards', frames `getCardImageKey`, 'back', 'shadow') whose frame is the hand card x DPR in EVEN device px, redrawn only on a size change; the layout's `card[kind].scale` maps that frame to CSS px (`cardTexture` in the layout), and every card the hand's size (hand, trick, trump, drawn) is the frame at exactly 1/DPR, its centre on a whole device px (`handPositions` snaps x), so it samples 1:1; the Phaser config's `roundPixels: true` snaps quads to device px. The canvas renders at DPR (`phaser/backingStore.js`: backing = CSS x DPR, scale zoom 1/DPR, camera zoom DPR; world units stay CSS px; never add a `render` block to the Phaser config: Phaser then reads `transparent` from it). `phaser/loopControl.js` sleeps the Phaser loop off TABLE/GAME_END (after one frame, outside the rAF callback: 3.55 re-requests after its callback) and wakes it on enterTable; the fake clock stops scene time while asleep. Opponent avatars and the frog are built once per game and updated in place (`OpponentManager.avatarBuilds`; the avatar click reads `dataset.username`, the seat's player now)
