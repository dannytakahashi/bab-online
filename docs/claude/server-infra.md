# Server: database, caches, limits, HTTP pages and avatars

Never auto-loaded: open it for `server/database.js`, DB reads/writes, profile caches, soft rate limits, the Express pages or the avatar pipeline.

## Startup DB and indexes

- Startup DB (`server/database.js`): `connectDB` runs fire-and-forget after `listen()`, retries the connect with backoff (2 s doubling, max 30 s), assigns the collections and resolves `whenReady()`, then `ensureIndexes()` (`Promise.allSettled` of `safeIndex` per index: `gameRecords.completedAt_-1`, `reports.createdAt_-1`, unique `users.username_1` via `ensureUsernameIndex`); each failure is a warning and startup continues (existing duplicates → no unique index, but a non-unique `username_nonunique` fallback so lookups stay indexed; a later boot drops the fallback and retries the unique build). Only `createIndex` (MongoDB 4.0+); no backfills. `signIn`/`restoreSession`/`signUp` and the `rejoinGame` token check wait up to 10 s on `whenReady` when the collection is still undefined (a failed restore makes both clients forget their token). `server/__tests__/realMongo.test.js` checks indexes/plans/race/payload equality against a localhost mongod (scratch DB, skips green without one; never call `connectDB` from tests: its dbName is `babonline`)
- `users.username` has a unique index, created at startup (`ensureUsernameIndex`); if existing duplicates block it the server logs a warning and runs with the non-unique `username_nonunique` fallback until they are merged. `signUp` treats a duplicate-key error as "That name is taken." Active-game DB writes (`setActiveGame`, `clearActiveGameForAll`) go to each seat's `ownerUsername` (none for native bots; `setActiveGame` also skips resigned and gone seats); `clearActiveGameForAll` only clears users whose `activeGameId` is still that game (a leaver may be in another game by then). Both run as one `Promise.all` of the per-user helpers (deliberately not `updateMany`: same latency at 4 users, per-user error isolation, the tests' `updateOne` spies), still awaited: game start writes before `teamsAnnounced` (sign-in auto-rejoin reads it) and re-clears every launched write if aborted meanwhile (and a seat's write if it was resigned or /leave'd during the batch); the end path clears before tournament scoring. Stale-pointer clears on signIn/restoreSession/rejoinFailed are scoped to the stale id (`clearActiveGame(u, staleId)`), so a pointer a new game wrote meanwhile survives

## DB reads and profile caches

- DB reads are projected (memoryDb supports projections, so tests see the real shape): signIn excludes `customProfilePic`/`stats`/`botStats`/`mergedFrom` (restoreSession also `password`); profile/leaderboard/search/records read only the fields their replies use. `handleDrawComplete` looks up the four saved pics in parallel with `getUserProfilePic(u, {randomFallback:false})` (null instead of a random pic) and the unchanged loop draws every random pic in `drawIDs` order — never let lookups draw randoms concurrently (seeded fixtures/transcripts/sim depend on the order)
- Stats scopes (owner 2026-11-13: "you can choose to see standings including human and bot games, human only, or human plus bot only ... default to human only"; `server/utils/statsScope.js`): `users.stats` stays the HUMAN-games bucket exactly as before (same fields and rules; every shipped iOS build and every existing reader sees it); a game with any `bot` or `resignBot` seat at the end (solo games, tournament tables with filler bots, a resigned seat) `$inc`s the parallel `users.botStats` (same 12 fields) for every seat with a human owner (the `getOriginalPlayer` + `ownerUsername` rule: lazy, resigned and /leave'd owners included) and inserts its `gameRecords` entry with `withBots: true`, `team1Players`/`team2Players` holding ONLY the human owners (seat order, `recordName`) and `team1Bots`/`team2Bots` the persona names of the seats without an owner ('🤖 Mary'; a team of two bots has `teamNPlayers: []`). Bots are never in `teamNPlayers`, so merge / rename / delete never touch a bot name. A lazy-only game stays human; a game with no human owner (ambient demo) records nothing and invalidates nothing. Nothing from before 2026-11-13 exists for bot games (no backfill). Readers: `getProfile` / `getLeaderboard` / `getRecords` / `getPlayerProfile` take an optional `{scope: 'human'|'bots'|'all'}` (`normalizeScope`: missing, non-object or unknown = `human`, never refused; `getPlayerProfile`'s Joi key is `Joi.any()` so `stripUnknown` keeps it and a non-string, null or long scope is normalized, not refused; `socket/index.js` forwards the payload of the three safeHandler events; their c2s contract payload stays the open property-less one, documented by examples and notes, since a payload WITH properties needs a Joi schema and their `joi: null` is frozen by the baseline). `human` = today's reply byte for byte (`profile.stats` is the RAW stored bucket, a legacy 6-key document stays 6 keys; records filter `withBots: {$ne: true}`, same projection, still three finds, the thisMonth/thisYear finds still on `completedAt_-1`); `bots` = `botStats` / `withBots: true` records; `all` = `stats + botStats` summed field by field (`sumBuckets`) / every record. A leaderboard row exists for a player with `gamesPlayed > 0` IN THAT SCOPE (all: either bucket) and the Population row averages those rows. Records in bots / all: `players` = the humans then the bot personas (strings, the wire type is unchanged), and a team of two bots never holds the highest/lowest score or most/least bags (biggest win always has a human side). Echo rule: the reply carries a top-level `scope` ONLY when the request had a `scope` key (so iOS and every payload-less caller get exactly the old bytes; the web always sends one and drops a reply for another scope). leaderboardResponse / recordsResponse failures echo it too (iOS 1.2.1 build 8 files a failure under the scope that asked; the web drops a stale one); profile failures do not. `searchPlayers` rows stay human games (a lookup, not standings). Tests: `server/socket/__tests__/statsScope.test.js`, presence R20, tournamentLifecycle (filler-bot tables), realMongo (o), `server/admin/__tests__/botStatsMerge.test.js`
- Profile caches (`server/utils/ttlCache.js`, `profileHandlers.js`): leaderboard and records are 60 s single-flight caches, ONE PER SCOPE (`leaderboardCache[scope]`, `recordsCache[scope]`; records keyed by server-local year-month, and a month change clears every scope); a fill that overlaps an `invalidate()` is never stored; cached values are shared, never mutate them. Every `invalidateLeaderboard()` / `invalidateRecords()` clears all three scopes. Invalidated after `recordGameStats` (records after `recordGameResult`, both after the stat writes), `deleteAccount`, `updateProfilePic`/`uploadProfilePic`, an admin merge or rename. Test helpers `_peekLeaderboardCache(scope = 'human')`, `_peekRecordsCache(scope)`, `_resetCachesForTests()` (every scope). The owner CLIs (`merge-accounts`, `set-password`) run in another process: only the TTL covers them. Search stays the unanchored case-insensitive regex (it walks the `username_1` index keys; no `usernameLower` field by choice — no backfill, no Alan/alan collisions); a trimmed query longer than 50 answers `[]` without a read

## Soft limits

- Soft limits (`rateLimiter.limits`, per socket): `getLeaderboard`/`getRecords` 10/10 s are checked inside their handlers and over the limit reply with the cached (even stale) page OF THE REQUESTED SCOPE, its fill in flight, else the ordinary `{success:false, message}` — never `serverError` (one budget for every scope: fast switching counts against it; the web control coalesces quick switches, 200 ms); `searchPlayers`/`getPlayerProfile` 30/10 s through `asyncHandler` (`serverError {code:'rateLimit'}`, a web toast; Joi since V1_REMOVALS #18, as for `joinLobby` (a uuid) and `removeBot` (a `bot:` id; `removeBotFromLobby` also refuses a human member); both web-only). `contract/src/c2s.js` mirrors the wrapper metadata (contract.test checks it)

## Avatars

- Avatars (docs/avatars.md, invariants I1-I6): clients that send `clientHello {caps:['avatarUrl']}` (`server/socket/clientInfo.js`, `socket.data.client`; web sends it from `client/src/utils/avatar.js`) get null custom-picture slots plus additive `avatarUrls`/`avatarUrl` (`GET /avatar/:username?v=`, `server/routes/avatar.js`: immutable only on the current version, uniform 404, per-IP bucket via clientIp); every other socket (the App Store build, old web bundles) gets the small derived inline WebP in the same slot. Renditions are derived lazily in memory (`server/avatar/avatarStore.js`, sharp 0.34.5 pinned for Node 18; `warm` from getUserProfilePic, never blocking, no RNG) and mapped at emit time (`server/avatar/avatarWire.js`); room broadcasts (positionUpdate, playerActiveMode) stay ONE emit with inline + URL. Stored `customProfilePic` values are never rewritten; new uploads are stored as the canonical WebP. Kill switches: `AVATAR_LEGACY_INLINE=raw`, `AVATAR_PIPELINE=off` (default off under Jest: tests opt in with `avatarStore.configure({enabled:true})` + `_reset()`). Stock art: `client/assets/profileN.png` 192 px (same paths: the App Store app loads them) and `client/assets/avatars/v1/*.webp` (immutable; new art goes to v2); web renders every picture through `avatarSrc`/`applyAvatarImg` only. Removing the inline images waits in `contract/V1_REMOVALS.md` #19
